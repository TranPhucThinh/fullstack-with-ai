Module 0 · Bài 01

HTTP là gì — request/response, method, status code, header

Bóc tách giao thức nền tảng của toàn bộ web — thứ bạn vừa chạm tay vào ở Bài 00 mà chưa hiểu.

⏱ ~40 phút · 🎯 Mục tiêu: đọc được một request/response HTTP thật bằng mắt, giải thích được từng phần.

🌉 Bắc cầu từ cái bạn đã biết

Ở Bài 00, bạn gõ curl http://localhost:4000 và nhận về 200. Con số 200 đó là một HTTP status code — một mảnh của giao thức HTTP. Bài này mở toàn bộ bức tranh: khi trình duyệt hoặc curl "nói chuyện" với server, chúng trao đổi đúng một thứ gọi là HTTP message. Hiểu nó là hiểu nền móng của mọi framework bạn sắp học.

1. HTTP là gì — một "ngôn ngữ" giữa client và server

HTTP (HyperText Transfer Protocol) là giao thức — một bộ quy tắc — quy định cách một client (trình duyệt, curl, app mobile...) yêu cầu tài nguyên từ một server và cách server trả lời. Nó là "ngôn ngữ chung" mà mọi web server trên thế giới đều nói, nên bất kỳ client nào cũng nói chuyện được với bất kỳ server nào.

💡 Vì sao cần một "ngôn ngữ chung"?

Nếu mỗi server tự bịa cách trả lời riêng, trình duyệt phải học hàng triệu "phương ngữ". HTTP chuẩn hóa: client gửi request theo khuôn, server trả response theo khuôn — ai cũng hiểu ai. Đây là lý do web "chạy được" ở quy mô toàn cầu.

Theo tài liệu MDN về HTTP, HTTP là một giao thức client-server: client gửi request, server trả response. Mỗi request/response là một HTTP message có cấu trúc cố định.

2. Cấu trúc một HTTP request

Khi bạn gõ curl http://localhost:4000, curl gửi đi một request. Bạn có thể nhìn thấy nó bằng mắt bằng cờ -v (verbose). Chạy lệnh sau (server đang chạy ở terminal 1):

bash — terminal thứ hai 
# -v: in ra chi tiết request/response. -s: bỏ thanh tiến trình.
curl -sv http://localhost:4000

Bạn sẽ thấy một khối như thế này (phần > là request, phần < là response):

output — request (phần >) 
> GET / HTTP/1.1
> Host: localhost:4000
> User-Agent: curl/8.x.x
> Accept: */*

Một request HTTP gồm 3 phần:

PhầnVí dụÝ nghĩa
Request lineGET / HTTP/1.1Method + đường dẫn + phiên bản HTTP
HeadersHost: localhost:4000Thông tin phụ: ai gửi, gửi tới đâu, chấp nhận gì...
Body (tuỳ chọn)(trống ở GET)Dữ liệu gửi lên — thường dùng khi POST/PUT
💡 Vì sao request line quan trọng nhất?

Nó chứa method (client muốn làm gì) và path (làm trên tài nguyên nào). Server đọc đúng 2 thứ này là biết phải xử lý ra sao. Phần còn lại là "gia vị" giúp server hiểu ngữ cảnh.

3. HTTP methods — client "muốn làm gì"

Method là động từ mô tả hành động client muốn server thực hiện. Có 4 method chính bạn sẽ dùng suốt sự nghiệp:

MethodÝ nghĩaVí dụ dùng
GETLấy dữ liệu (không thay đổi gì)Xem danh sách khóa học
POSTTạo tài nguyên mớiĐăng ký tài khoản
PUTThay thế toàn bộ tài nguyênCập nhật toàn bộ hồ sơ
DELETEXóa tài nguyênXóa khóa học
💡 Vì sao phân biệt method quan trọng?

Vì nó quyết định tính an toàn và tính đơn điệu (idempotency) — khái niệm senior phải nắm. GET an toàn (không đổi dữ liệu), DELETE đơn điệu (gọi 10 lần cũng như 1 lần). Bài 02 (REST) và Bài 43 (transaction) sẽ đào sâu. Giờ chỉ cần nhớ: method nói lên ý định.

4. HTTP status codes — server "trả lời thế nào"

Server trả lời bằng một status code — 3 chữ số tóm tắt kết quả. Bạn đã thấy 200 ở Bài 00. Các nhóm chính:

NhómÝ nghĩaVí dụ
2xxThành công200 OK, 201 Created
3xxChuyển hướng301 Moved Permanently
4xxLỗi phía client400 Bad Request, 404 Not Found
5xxLỗi phía server500 Internal Server Error

Theo MDN — HTTP response status codes, status code là phần đầu của dòng trạng thái trong response, cho client biết request thành công hay thất bại và theo hướng nào.

💡 Vì sao phải nhớ "nhóm" chứ không học thuộc từng mã?

Vì khi gặp mã lạ (vd 418), bạn vẫn biết nó thuộc nhóm 4xx → lỗi phía client. Nhóm là "bộ khung", mã cụ thể là chi tiết. Senior không thuộc lòng 60 mã — họ đọc nhóm là đoán được vấn đề.

5. Cấu trúc một HTTP response

Phần < trong output curl -v là response — server trả lời:

output — response (phần <) 
< HTTP/1.1 200 OK
< Content-Type: text/plain; charset=utf-8
< Date: ...
< Connection: keep-alive
< Content-Length: 28

E-Learning API đang chạy! 🚀

Response gồm 3 phần:

PhầnVí dụÝ nghĩa
Status lineHTTP/1.1 200 OKPhiên bản + status code + lý do
HeadersContent-Type: text/plainMô tả response: kiểu dữ liệu, độ dài...
BodyE-Learning API đang chạy! 🚀Nội dung thật trả về
💡 Vì sao Content-Type quan trọng?

Nó báo cho client cách đọc body. Trong src/server.ts bạn ghi 'Content-Type': 'text/plain; charset=utf-8' — nghĩa là "đây là văn bản thường, mã UTF-8". Nếu server trả JSON mà quên set application/json, client sẽ không biết parse. Bài 03 (JSON) sẽ đào sâu.

6. Headers — "gia vị" của request và response

Headers là các cặp Tên: Giá trị mang thông tin phụ. Một số bạn sẽ gặp nhiều:

HeaderXuất hiện ởÝ nghĩa
HostRequestServer nào (tên miền + cổng)
Content-TypeCả haiKiểu dữ liệu của body
Content-LengthCả haiĐộ dài body (byte)
AuthorizationRequestChứng thực — bài 14+ sẽ dùng
Set-CookieResponseServer bảo client lưu cookie
✅ Bạn vừa đạt được
  • Đọc được một request/response HTTP thật bằng mắt (curl -v)
  • Phân biệt 3 phần của request (request line, headers, body) và response (status line, headers, body)
  • Biết 4 method chính (GET/POST/PUT/DELETE) và ý nghĩa từng nhóm status code (2xx/3xx/4xx/5xx)
  • Hiểu vì sao Content-Type quyết định cách client đọc body

7. Câu hỏi tư duy (bắc cầu sang bài sau)

Bạn vừa thấy GET / HTTP/1.1 — method GET và đường dẫn /. Nhưng một hệ thống e-learning có hàng chục "tài nguyên": khóa học, người dùng, bài giảng... Làm sao để thiết kế đường dẫn (/courses, /users...) và method sao cho có ý nghĩa, nhất quán, và dễ đoán? Đó chính là REST API — bài tiếp theo.
