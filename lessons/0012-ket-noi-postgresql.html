🌉 Bắc cầu từ cái bạn đã biết

Bài 10–11 bạn có server Express với routes, nhưng dữ liệu nằm trong mảng courses trong bộ nhớ — restart là mất. Bạn sẽ thấy mọi thứ từ bài 02 (REST resource) giờ có database thật đằng sau.

1. Vì sao cần database — và PostgreSQL là gì

Cho tới giờ dữ liệu nằm trong mảng JavaScript trong bộ nhớ tiến trình. Điều này có 3 vấn đề:

Vấn đề (mảng trong bộ nhớ)Giải pháp (database)
Restart server là mất hết dữ liệuDatabase lưu trên đĩa, bền vững qua restart
Nhiều tiến trình server không dùng chung đượcDatabase là nơi tập trung, mọi server cùng đọc/ghi
Không truy vấn được: "users nào đăng ký tháng này?", "khóa học giá > X"SQL cho phép lọc, sắp xếp, gộp nhóm, join bảng

Theo PostgreSQL Official Docs, PostgreSQL là "a powerful, open source object-relational database system" — hệ quản trị cơ sở dữ liệu quan hệ mã nguồn mở, dùng SQL chuẩn, có transactions, có index. Đây là database phổ biến được NestJS hỗ trợ tốt (TypeORM), đúng mission của bạn.

2. Bật PostgreSQL bằng Docker

Bạn đã có docker-compose.yml từ bài 00 khai báo container elearning-postgres (PostgreSQL 16-alpine, user/password/db đều elearning). Container đang tồn tại nhưng có thể đã tắt. Bật lên:

Terminal — từ thư mục elearning-backend/ 
# Bật container PostgreSQL (lần đầu sẽ tạo từ image có sẵn)
docker start elearning-postgres

# Kiểm tra xem nó đã nhận kết nối chưa
docker exec elearning-postgres pg_isready -U elearning -d elearning
# /var/run/postgresql:5432 - accepting connections
💡 Vì sao dùng Docker cho PostgreSQL?

Bạn không cần cài PostgreSQL native lên macOS. Docker cô lập môi trường: image chuẩn, cùng version với production, dữ liệu nằm trong volume pgdata (khai báo ở docker-compose) nên không mất khi tắt container. Clone repo là chạy được — đó là hạ tầng dạng mã (infrastructure-as-code).

Kiểm tra nhanh bằng lệnh SQL trong container:

Terminal — xem có bảng nào chưa 
docker exec -it elearning-postgres psql -U elearning -d elearning -c '\dt'
# Did not find any relations. — chưa có bảng nào, đúng như kỳ vọng

3. Thư viện pg (node-postgres)

pg là thư viện Node chính thức để nói chuyện với PostgreSQL — đã có sẵn trong package.json (pg@^8.23.0 + @types/pg) nên không cần cài lại. Nếu dự án clone mới, chạy npm install ở thư mục elearning-backend/ là đủ.

Theo node-postgres docs, pg tự đọc các biến môi trường PGHOST, PGPORT, PGUSER, PGPASSWORD, PGDATABASE. Bạn đã biết cách dùng env ở bài 08 — giờ áp dụng cho database. Thêm vào .env (file đã bị ignore, không commit):

.env — thêm thông tin kết nối PostgreSQL 
# Server Express
PORT=4000

# PostgreSQL (khớp với docker-compose.yml)
PGHOST=localhost
PGPORT=5432
PGUSER=elearning
PGPASSWORD=elearning_dev_password
PGDATABASE=elearning

Để Node nạp file .env vào process.env, Node 24 có sẵn process.loadEnvFile() (không cần cài dotenv). Theo Node.js docs, lệnh mặc định đọc ./.env.

4. Kết nối database bằng pool.query()

Tạo file src/db.ts chuyên chứa kết nối:

src/db.ts — kết nối PostgreSQL (File MỚI, cần tự tạo trong editor) 
// src/db.ts — nơi duy nhất quản lý kết nối database
import pg from 'pg'
import { loadEnvFile } from 'node:process'

loadEnvFile() // nạp .env vào process.env — Node 24 có sẵn

// Pool: "bể bơi" kết nối dùng chung — pg tự đọc PG* env vars
export const pool = new pg.Pool()

// Kiểm tra kết nối thật — chạy server sẽ thấy dòng này nếu database OK
pool.query('SELECT 1')
  .then(() => console.log('✅ Database connected'))
  .catch((err) => console.error('❌ Database error:', err.message))
💡 Vì sao dùng Pool?

Theo node-postgres docs, mỗi truy vấn mở một kết nối TCP tốn chi phí. Pool giữ sẵn vài kết nối, dùng chung cho mọi pool.query() — đúng chuẩn production. Mỗi request Express dùng pool, không phải mở kết nối mới.

Lưu ý: loadEnvFile() chạy một lần ở module import — khi server khởi động. Đây là chi tiết quan trọng: new pg.Pool() đọc env ngay lúc tạo.

5. Tạo bảng users bằng SQL thật

SQL để tạo bảng — chạy trực tiếp trong container để hiểu bản chất (sau này sẽ học migrations):

Terminal — SQL CREATE TABLE users 
docker exec -it elearning-postgres psql -U elearning -d elearning -c "CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL
);"
Phần SQLÝ nghĩa
SERIAL PRIMARY KEYTự tăng id, là khóa chính (mỗi dòng duy nhất)
TEXT UNIQUE NOT NULLChuỗi, không trùng lặp, bắt buộc có
TEXT NOT NULLChuỗi bắt buộc có

Theo PostgreSQL docs CREATE TABLE, SERIAL là kiểu tự tăng id và PRIMARY KEY định nghĩa khóa chính — nền tảng cho mọi bảng sau này.

6. CRUD users qua Express + SQL thật

Giờ nối Express với database: thay vì đọc/ghi mảng, các route dùng pool.query(). Thay toàn bộ src/server.ts:

src/server.ts — Express + PostgreSQL CRUD users (THAY TOÀN BỘ) 
import express, { type Request, type Response } from 'express'
import cors from 'cors'
import { pool } from './db.js'

const app = express()
app.use(cors())
app.use(express.json())

// GET /api/users — đọc toàn bộ users từ database
app.get('/api/users', async (req: Request, res: Response) => {
  const { rows } = await pool.query('SELECT id, email, name FROM users ORDER BY id')
  res.json(rows)
})

// POST /api/users — tạo user mới, trả về dòng vừa tạo kèm id (SERIAL)
app.post('/api/users', async (req: Request, res: Response) => {
  const { email, name } = req.body ?? {}
  if (!email || !name) {
    res.status(400).json({ error: 'email và name là bắt buộc' })
    return
  }
  const { rows } = await pool.query(
    'INSERT INTO users (email, name) VALUES ($1, $2) RETURNING id, email, name',
    [email, name],
  )
  res.status(201).json(rows[0])
})

// GET /api/users/:id — lấy 1 user
app.get('/api/users/:id', async (req: Request, res: Response) => {
  const id = Number(req.params.id) // ép kiểu id từ URL về số
  if (!Number.isInteger(id)) {
    res.status(404).json({ error: 'User not found' })
    return
  }
  const { rows } = await pool.query('SELECT id, email, name FROM users WHERE id = $1', [id])
  if (rows.length === 0) res.status(404).json({ error: 'User not found' })
  else res.json(rows[0])
})

// PUT /api/users/:id — cập nhật name/email
app.put('/api/users/:id', async (req: Request, res: Response) => {
  const { email, name } = req.body ?? {}
  const id = Number(req.params.id)
  if (!Number.isInteger(id)) {
    res.status(404).json({ error: 'User not found' })
    return
  }
  const { rows } = await pool.query(
    'UPDATE users SET email = $1, name = $2 WHERE id = $3 RETURNING id, email, name',
    [email, name, id],
  )
  if (rows.length === 0) res.status(404).json({ error: 'User not found' })
  else res.json(rows[0])
})

// DELETE /api/users/:id — xóa user
app.delete('/api/users/:id', async (req: Request, res: Response) => {
  const id = Number(req.params.id)
  if (!Number.isInteger(id)) {
    res.status(404).json({ error: 'User not found' })
    return
  }
  const { rowCount } = await pool.query('DELETE FROM users WHERE id = $1', [id])
  if (rowCount === 0) res.status(404).json({ error: 'User not found' })
  else res.status(204).end()
})

const PORT = Number(process.env.PORT ?? 4000)
app.listen(PORT, () => console.log(`✅ Express running at http://localhost:${PORT}`))
💡 Vì sao dùng $1, $2 thay vì nối chuỗi?

Đây là parameterized query: value được truyền riêng, database tự escape. Nếu nối '... VALUES ('${email}')' thì người dùng gửi x'; DROP TABLE users;-- sẽ chạy được SQL của họ — đó là SQL injection, lỗ hổng kinh điển. pg nhận tham số qua mảng, xử lý an toàn. Đây là thói quen production bắt buộc.

⚠️ Lỗi trang web thường gặp: email trùng

Vì cột email có UNIQUE, POST user trùng email sẽ ném lỗi 23505 từ database và server có thể trả 500. Bài này chấp nhận (mới học CRUD); bài 14 (auth) sẽ bắt lỗi này trả 409 và xử lý đúng cách. Cũng lưu ý: chưa có error-handling middleware ở code trên — nếu query lỗi, Express 5 trả HTML mặc định; bạn có thể giữ error-handler từ bài 11 bằng cách thêm lại.

8. Tổng kết — bạn vừa đạt được

  • Bật PostgreSQL bằng Docker, kiểm tra kết nối bằng pg_isready/psql
  • Kết nối database bằng pg.Pool + env vars (loadEnvFile() Node 24)
  • Tạo bảng users bằng SQL thật (SERIAL, PRIMARY KEY, UNIQUE, NOT NULL)
  • Viết CRUD users qua Express + pool.query() với parameterized query chống SQL injection
  • Dữ liệu bền vững: restart server không mất
