Middleware nâng cao — error, logging, CORS

Viết middleware log của riêng bạn, hiểu error-handling middleware (4 tham số!), và bật CORS cho frontend — ba thứ mọi API production đều cần.

⏱ ~60 phút · 🎯 Mục tiêu: server e-learning có middleware log tự viết, error-handling trả JSON 500 thay vì crash, và CORS bật cho frontend — verify bằng curl.

🌉 Bắc cầu từ cái bạn đã biết

Bài 10 bạn đã dùng middleware có sẵn express.json() — nó đọc body rồi gọi next() để request đi tiếp. Bài này bạn tự viết middleware: một hàm (req, res, next) làm việc của mình rồi gọi next(). Đồng thời học hai middleware quan trọng: error-handling (chống crash) và CORS (cho frontend gọi API).

1. Middleware log tự viết — thấy request bằng mắt

Theo tài liệu chính thức Express: "Middleware functions are functions that have access to the request object (req), the response object (res), and the next function in the application's request-response cycle." Và quan trọng: "If the current middleware function does not end the request-response cycle, it must call next() to pass control to the next middleware function. Otherwise, the request will be left hanging."

Docs đưa ví dụ myLogger — in "LOGGED" mỗi khi có request đi qua. Ta nâng cấp thành log có timestamp + method + URL:

src/server.ts — thêm middleware log (đặt TRƯỚC các route) 
import express, { type Request, type Response, type NextFunction } from 'express'

// Middleware log tự viết — chạy cho MỌI request, theo thứ tự khai báo
app.use((req: Request, res: Response, next: NextFunction) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`)
  next() // BẮT BUỘC gọi — không gọi thì request treo, client chờ mãi
})
💡 Vì sao phải đặt TRƯỚC route?

Docs nhấn mạnh: "The order of middleware loading is important: middleware functions that are loaded first are also executed first. If myLogger is loaded after the route to the root path, the request never reaches it... because the route handler terminates the request-response cycle." — Route handler trả response xong là request kết thúc, middleware khai báo sau không bao giờ chạy.

2. Error-handling middleware — 4 tham số, chống crash

Khi một handler ném lỗi (vd đọc database lỗi), nếu không xử lý, Express 5 sẽ trả về HTML lỗi mặc định — không phải JSON API của bạn. Giải pháp: error-handling middleware, nhận biết bằng 4 tham số (err, req, res, next). Docs: "If you pass anything to the next() function (except the string 'route' or 'router'), Express regards the current request as being an error and will skip any remaining non-error handling routing and middleware functions."

src/server.ts — error-handling middleware (đặt SAU CÙNG, sau mọi route) 
// Route cố tình ném lỗi để test (thêm tạm, xong bài thì xóa)
app.get('/api/boom', () => {
  throw new Error('Có lỗi xảy ra!')
})

// Error-handling middleware — 4 tham số (err, req, res, next) là DẤU HIỆU NHẬN BIẾT
app.use((err: Error, req: Request, res: Response, next: NextFunction) => {
  console.error('Lỗi:', err.message) // ghi log lỗi ra terminal
  res.status(500).json({ error: 'Internal Server Error' }) // trả JSON thay vì HTML mặc định
})
⚠️ Vì sao Express biết đây là error-handler?

Express nhận biết bằng số tham số: hàm có đúng 4 tham số (err, req, res, next) được coi là error-handling middleware. Hàm 3 tham số (req, res, next) là middleware thường. Đừng bỏ tham số err — nếu chỉ viết (req, res, next) thì nó thành middleware thường và không bắt được lỗi.

3. CORS — cho frontend gọi API từ domain khác

Trình duyệt chặn JavaScript gọi API từ domain khác (Same-Origin Policy). Khi frontend React của bạn (chạy ở localhost:3000) gọi backend (localhost:4000), trình duyệt sẽ chặn trừ khi server trả header Access-Control-Allow-Origin. Express có middleware cors chính thức làm việc này.

Terminal — cài cors 
npm install cors
npm install -D @types/cors
src/server.ts — bật CORS (đặt đầu tiên, trước mọi thứ) 
import cors from 'cors'

const app = express()
app.use(cors()) // cho phép mọi origin gọi API — đủ cho dev; production sẽ giới hạn danh sách
app.use(express.json())
💡 Vì sao cors() đặt đầu tiên?

Header CORS phải có mặt trong mọi response, kể cả response lỗi. Đặt cors() đầu tiên đảm bảo nó chạy trước mọi thứ khác — kể cả error-handler — nên response nào cũng có header CORS. Đây là lý do thứ tự middleware quan trọng (bài 10 đã thấy với express.json).

4. Ghép lại — server.ts hoàn chỉnh bài 11

src/server.ts — thêm 3 middleware vào code bài 10 của bạn 
import express, { type Request, type Response, type NextFunction } from 'express'
import cors from 'cors'
import { courses, createCourseId } from './courses.js'

const app = express()
app.use(cors()) // 1. CORS — cho frontend gọi từ domain khác
app.use(express.json()) // 2. đọc body JSON

// 3. Middleware log tự viết — chạy cho MỌI request
app.use((req: Request, res: Response, next: NextFunction) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`)
  next()
})

// ——— Các route giữ nguyên từ bài 10 ———
app.get('/api/courses', (req: Request, res: Response) => { /* ... */ })
app.get('/api/courses/:id', (req: Request, res: Response) => { /* ... */ })
app.post('/api/courses', (req: Request, res: Response) => { /* ... */ })

// Route test lỗi — xóa sau khi verify
app.get('/api/boom', () => {
  throw new Error('Có lỗi xảy ra!')
})

// Error-handling middleware — 4 tham số, đặt SAU CÙNG
app.use((err: Error, req: Request, res: Response, next: NextFunction) => {
  console.error('Lỗi:', err.message)
  res.status(500).json({ error: 'Internal Server Error' })
})

const PORT = Number(process.env.PORT ?? 4000)
app.listen(PORT, () => {
  console.log(`✅ Express running at http://localhost:${PORT}`)
})
