REST API — resource, URL design

Biến HTTP thành một ngôn ngữ thiết kế API có quy tắc — và dự án của bạn có endpoint thật đầu tiên trả JSON.

⏱ ~45 phút · 🎯 Mục tiêu: server của bạn trả danh sách khóa học dạng JSON qua GET /api/courses — mẩu chạy được đầu tiên có routing thật.

🌉 Bắc cầu từ cái bạn đã biết

Bài 01 bạn biết HTTP có method (GET/POST/PUT/DELETE) và status code (200/404...). Nhưng mới chỉ có một đường dẫn /. Một hệ thống e-learning có hàng chục "thứ" cần quản lý: khóa học, người dùng, bài giảng... REST là bộ quy tắc trả lời câu hỏi: làm sao thiết kế đường dẫn và method cho có ý nghĩa, nhất quán, dễ đoán.

1. REST là gì — "tài nguyên" là trung tâm

REST (Representational State Transfer) là một phong cách kiến trúc API. Ý tưởng cốt lõi: mọi thứ hệ thống quản lý — khóa học, người dùng, đơn hàng — là một resource (tài nguyên). Mỗi resource có một định danh (URL) và được thao tác bằng HTTP method chuẩn.

💡 Vì sao gọi là "Representational"?

Server không gửi "khóa học" vật lý — nó gửi một biểu diễn (representation) của khóa học, thường là JSON. Client nhận JSON, hiển thị, sửa, gửi lại. Đó là lý do API trả JSON chứ không trả "đối tượng" — bạn đang trao đổi biểu diễn của tài nguyên.

Theo MDN — REST, REST là một kiến trúc phần mềm cho phép client và server giao tiếp qua HTTP, dựa trên tài nguyên và các method chuẩn.

2. URL design — danh từ số nhiều, không động từ

Quy tắc vàng của REST: URL chỉ tài nguyên (danh từ), còn hành động nằm ở method. So sánh:

❌ Sai (hành động trong URL)✅ Đúng (tài nguyên + method)Ý nghĩa
GET /getCoursesGET /api/coursesLấy danh sách khóa học
POST /createCoursePOST /api/coursesTạo khóa học mới
GET /deleteCourse?id=5DELETE /api/courses/5Xóa khóa học id=5
💡 Vì sao "danh từ số nhiều"?

/api/courses là bộ sưu tập (collection) — GET lấy cả bộ, POST thêm phần tử. /api/courses/5 là một phần tử (item) — GET lấy nó, DELETE xóa nó. Quy ước này làm API dễ đoán: thấy URL là đoán được method nào hợp lệ, không cần đọc tài liệu.

3. Method mapping — hành động lên resource

Với mỗi resource, 4 method chuẩn tạo thành vòng đời CRUD:

MethodURLHành độngStatus code thành công
GET/api/coursesLấy danh sách200 OK
GET/api/courses/5Lấy 1 khóa học200 OK / 404 nếu không có
POST/api/coursesTạo mới201 Created
PUT/api/courses/5Thay thế toàn bộ200 OK
DELETE/api/courses/5Xóa204 No Content
💡 Vì sao POST trả 201, DELETE trả 204?

Status code không chỉ "thành công hay không" — nó kể chi tiết. 201 Created báo "đã tạo, đây là thứ mới". 204 No Content báo "đã xóa, không còn gì để trả". Client dựa vào đó để xử lý đúng — đây là chi tiết phân biệt junior và senior khi thiết kế API.

4. Thực hành — server REST đầu tiên của dự án

Giờ thay src/server.ts bằng server REST: trả danh sách khóa học JSON qua GET /api/courses, chi tiết qua GET /api/courses/:id, và 404 cho mọi thứ khác. Mở file src/server.ts trong editor và thay toàn bộ nội dung:

src/server.ts 
import { createServer } from 'node:http'

// Dữ liệu khóa học tạm — chưa có database, bài 12 sẽ thay bằng PostgreSQL
const courses = [
  { id: 1, title: 'NestJS cơ bản', price: 500000 },
  { id: 2, title: 'Design Pattern cho Backend', price: 800000 },
]

// Tạo server: mỗi request tới, hàm này nhận (req, res)
const server = createServer((req, res) => {
  // Phân tích URL: path (đường dẫn) và query (tham số ?...)
  const url = new URL(req.url ?? '/', `http://${req.headers.host}`)
  const path = url.pathname

  // Routing: so khớp path với từng tài nguyên
  if (req.method === 'GET' && path === '/api/courses') {
    // Trả danh sách khóa học dạng JSON
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' })
    res.end(JSON.stringify(courses))
    return
  }

  // Pattern /api/courses/:id — lấy id từ path bằng regex
  const match = path.match(/^\/api\/courses\/(\d+)$/)
  if (req.method === 'GET' && match) {
    const id = Number(match[1])
    const course = courses.find((c) => c.id === id)
    if (course) {
      res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' })
      res.end(JSON.stringify(course))
    } else {
      // Không tìm thấy → 404 Not Found
      res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' })
      res.end(JSON.stringify({ error: 'Course not found' }))
    }
    return
  }

  // Mọi request khác → 404
  res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' })
  res.end(JSON.stringify({ error: 'Route not found' }))
})

const PORT = 4000
const HOST = '0.0.0.0'

server.listen(PORT, HOST, () => {
  console.log(`✅ Server chạy tại http://localhost:${PORT}`)
})
💡 Vì sao dùng regex để bắt id?

Node thuần chưa có "route pattern" như Express. Regex /^\/api\/courses\/(\d+)$/ khớp đúng dạng /api/courses/5 và bắt số id vào nhóm match[1]. Bài 07 sẽ đào sâu routing thủ công; bài 10 (Express) cho bạn thấy framework làm việc này gọn hơn thế nào.

5. Chạy và kiểm tra — sanity check

Server đang chạy ở terminal 1 với npm run dev sẽ tự reload khi bạn lưu file (tsx watch). Mở terminal thứ hai và kiểm tra:

bash — terminal thứ hai 
# Lấy danh sách khóa học — phải trả JSON 2 khóa học, HTTP 200
curl -s -w "\nHTTP:%{http_code}" http://localhost:4000/api/courses
output mong đợi 
[{"id":1,"title":"NestJS cơ bản","price":500000},{"id":2,"title":"Design Pattern cho Backend","price":800000}]
HTTP:200
bash — chi tiết + 404 
# Lấy khóa học id=2 — phải trả JSON đúng khóa học, HTTP 200
curl -s -w "\nHTTP:%{http_code}" http://localhost:4000/api/courses/2

# Khóa học không tồn tại — phải trả {"error":"Course not found"}, HTTP 404
curl -s -w "\nHTTP:%{http_code}" http://localhost:4000/api/courses/99

# Đường dẫn không tồn tại — phải trả {"error":"Route not found"}, HTTP 404
curl -s -w "\nHTTP:%{http_code}" http://localhost:4000/api/unknown
✅ Đã kiểm chứng trên máy thật

Code mẫu trên đã chạy XANH trong sandbox sạch dùng đúng package.json + package-lock.json của dự án bạn: tsc exit 0, 4 trường hợp curl trả đúng JSON + đúng status code (200/200/404/404). Bạn làm theo đúng thứ tự sẽ ra kết quả y hệt.
