Vì sao cần framework? Bài toán Express giải quyết

Nhìn lại 5 mảnh bạn đã tự xây tay ở các bài 06–08, rồi thấy Express đóng gói sẵn đúng từng mảnh đó — để hiểu bản chất trước khi dùng.

⏱ ~45 phút · 🎯 Mục tiêu: kể được 1-1 từng thứ bạn tự code bằng Node thuần tương ứng với API nào của Express, và giải thích được vì sao middleware là ý tưởng cốt lõi khiến framework thắng.

🌉 Bắc cầu từ cái bạn đã biết

Ở bài 07 bạn tự viết bảng route { method, pattern, handler }, hàm parseQuery, hàm readBody gom body từ stream, và validation thủ công. Ở bài 08 bạn dùng process.env để cấu hình PORT. Bài này không dạy thứ mới — nó đối chiếu: mỗi dòng bạn đã viết tay, Express có sẵn một API đúng chỗ đó. Khi hiểu được sự tương ứng này, bạn dùng Express không bao giờ bị "ma thuật".

1. Bạn đã tự xây gì? — 5 mảnh ghép của mọi web server

Hãy nhìn lại code src/server.ts bạn đang có — nó đã thao tác đủ 5 bài toán mà mọi web server phải giải, dù viết tay hay dùng framework:

#Bài toánBạn đã tự viết (bài 07–08)
1Định tuyến (routing)Mảng routes với { method, pattern, handler } + vòng lặp match regex
2Đọc query stringHàm parseQuery dùng URLSearchParams
3Đọc body (JSON)Hàm readBody — for await (const chunk of req) rồi JSON.parse

💡 Điểm cốt lõi

Framework KHÔNG làm điều gì khác — nó đóng gói 5 bài toán đó thành API chuẩn, để bạn không phải viết lại từ đầu mỗi dự án, và để team có chung một quy ước. Hiểu được 5 mảnh này là hiểu được xương sống của Express.

2. Express — mỗi mảnh có một API tương ứng

Theo tài liệu chính thức Express: "A route method is derived from one of the HTTP methods, and is attached to an instance of the express class." Nghĩa là thay vì bảng route của bạn, Express đưa method thành hàm: app.get(), app.post(), app.put(), app.delete()...

So sánh: bảng route (bài 07) vs app.METHOD (Express) 
// ——— BẠN ĐÃ TỰ VIẾT (bài 07) ———
const routes = [
  { method: 'GET',  pattern: /^\/api\/courses$/,         handler: listCourses },
  { method: 'GET',  pattern: /^\/api\/courses\/(\d+)$/, handler: getCourse },
  { method: 'POST', pattern: /^\/api\/courses$/,         handler: createCourse },
]
// … rồi vòng for match từng route, nếu không match thì trả 404

// ——— EXPRESS (bài 10 sẽ học) ———
import express from 'express'
const app = express()

app.get('/api/courses', listCourses)        // method + path + handler — tương đương 1 dòng trong bảng route
app.get('/api/courses/:id', getCourse)    // :id là path parameter — tương đương regex (\d+) của bạn
app.post('/api/courses', createCourse)

2.1. Routing: :id thay cho regex

Bạn từng viết /^\/api\/courses\/(\d+)$/ rồi lấy match[1]. Theo docs, Express có route parameters: "Route parameters are named URL segments that are used to capture the values specified at their position in the URL. The captured values are populated in the req.params object." — :id trong path, giá trị nằm ở req.params.id. Chính là match[1] của bạn, nhưng có tên và không cần tự viết regex.

Trích docs Express — req.params 
Route path: /users/:userId/books/:bookId
Request URL: http://localhost:3000/users/34/books/8989
req.params: { "userId": "34", "bookId": "8989" }

2.2. Query: req.query thay cho parseQuery

Hàm parseQuery của bạn dùng URLSearchParams để biến ?limit=1 thành object. Express có sẵn req.query — cũng là object từ query string. (Docs nhắc: "Query strings are not part of the route path" — tức query không nằm trong pattern route, mà nằm riêng ở req.query.)

2.3. Body: express.json() thay cho readBody

Hàm readBody của bạn gom chunk từ stream rồi JSON.parse. Express đóng gói chính xác việc này trong một middleware tên express.json() — sau khi chạy, body đã parse sẵn nằm ở req.body. Bạn học bài 07 để hiểu dưới nền nó làm gì, giờ chỉ cần gọi đúng middleware.

2.4. Response: res.json() thay cho sendJson

Hàm sendJson của bạn: writeHead(200, {'Content-Type': 'application/json'}) + end(JSON.stringify(data)). Express có res.json(data) — vừa set Content-Type đúng, vừa stringify, vừa kết thúc response. Docs liệt kê res.json() trong các "methods that send a response to the client, and terminate the request-response cycle"; còn cảnh báo: "If none of these methods are called from a route handler, the client request will be left hanging" — giống hệt bài học res.end() ở bài 06.

💡 Vì sao framework thắng — không phải vì "nhanh hơn"

Code Express không chạy nhanh hơn code tay của bạn (bản chất vẫn là node:http bên dưới). Nó thắng vì: (1) không viết lại 5 bài toán này mỗi dự án; (2) quy ước chung cho cả team (ai cũng biết req.params, req.query, req.body nghĩa là gì); (3) hệ sinh thái middleware — ý tưởng tiếp theo.

3. Middleware — thứ bạn CHƯA tự xây, và là lý do framework tồn tại

5 mảnh trên bạn đều có thể tự viết tay. Nhưng có một bài toán bạn chưa từng giải: các bước dùng chung cho mọi route — ghi log, kiểm tra auth, đọc body, ... nếu không có cơ chế chung, bạn phải lặp lại code đó trong từng handler. Đây chính là câu hỏi tư duy cuối bài 08.

Express giải bằng ý tưởng middleware: mỗi hàm (req, res, next) làm xong việc của mình rồi gọi next() để chuyển request sang hàm kế tiếp — như một đường ống. Chính docs gọi handler của Express là middlewares: "You can provide multiple callback functions that behave like middleware to handle a request. The only exception is that these callbacks might invoke next('route') to bypass the remaining route callbacks."

Ý tưởng middleware — ba hàm nối tiếp nhau như đường ống 
// Mỗi middleware: (req, res, next) => {…}; gọi next() để chuyển tiếp
app.use(logRequest)        // 1. ghi log mọi request
app.use(express.json())   // 2. đọc + parse body (chính là readBody của bạn)
app.use(checkAuth)        // 3. kiểm tra token — không qua thì trả 401, không gọi next()

app.get('/api/courses', listCourses)  // 4. tới đây là handler cuối — trả dữ liệu
✅ Bạn vừa đạt được
  • Kể được 5 bài toán mọi web server phải giải (routing, query, body, validation, env)
  • Đối chiếu 1-1 từng thứ bạn tự viết tay với API Express: app.METHOD ↔ bảng route, :id ↔ regex, req.query ↔ parseQuery, express.json() ↔ readBody, res.json() ↔ sendJson
  • Hiểu middleware là đường ống (req, res, next) — giải bài toán "code dùng chung cho mọi route" mà bạn chưa giải ở bài 07–08
