Chạy TypeScript với Node — tsx, tsconfig, build ra dist

Node chỉ hiểu JavaScript — TypeScript phải được biên dịch. Phân biệt hai luồng: dev (tsx) và production (tsc build), rồi khai thác tsconfig đúng mức.

⏱ ~60 phút · 🎯 Mục tiêu: build được dự án ra dist/ và chạy bằng node, thêm script build/typecheck/start:prod vào package.json, và giải thích được vì sao tsx không bắt lỗi type.

🌉 Bắc cầu từ cái bạn đã biết

Từ bài 00 bạn chạy mọi thứ bằng npx tsx — kể cả decorators ở bài 17. Nhưng bạn có để ý tsx không hề tạo ra file .js nào? Nó "biên dịch on-the-fly rồi vứt đi". Vậy khi đưa lên server production, cái gì chạy? Câu trả lời là tsc biên dịch ra dist/ rồi node chạy JavaScript thuần. Bài này làm rõ hai luồng đó — và đây chính là cách NestJS chạy production (bài 20+ sẽ dùng lại hệt).

1. Vì sao TypeScript không chạy trực tiếp trên Node

Node là runtime JavaScript — engine V8 chỉ hiểu JS, không hiểu cú pháp TS như : number, interface, <T>. Theo Node.js docs, để chạy TS bạn phải biên dịch sang JS trước. Có hai cách làm việc này:

CáchCông cụCó tạo file .js?Typecheck?Dùng khi
Biên dịch on-the-flytsx (esbuild)Không❌ KhôngDev — muốn nhanh + auto-reload
Biên dịch thật ra filetscCó → dist/✅ CóProduction / CI
💡 Điểm mấu chốt — tsx và tsc KHÁC nhau ở "typecheck"

tsx dùng esbuild để bóc type cực nhanh — nhưng không kiểm tra type có đúng không. tsc vừa bóc type vừa kiểm tra, rồi phát ra file .js. Hệ quả: chạy tsx mà code có lỗi type thì vẫn "chạy xanh"; chỉ tsc mới bắt được. Đây là lý do senior luôn giữ một lệnh typecheck trong CI, độc lập với việc "chạy được".

2. Minh chứng — tsx không bắt lỗi type, tsc thì bắt

Thử với một dòng code sai type rõ ràng (const n: number = 'không phải số'):

Terminal — cùng một file, hai kết quả khác nhau (đã verify thật) 
# 1) tsx: bóc type rồi chạy — KHÔNG phàn nàn, vẫn in ra
$ npx tsx typecheck-gap.ts
tsx vẫn chạy: không phải số          # ← exit 0, không có lỗi gì

# 2) tsc: kiểm tra type — BẮT lỗi ngay lập tức
$ npx tsc --noEmit typecheck-gap.ts
error TS2322: Type 'string' is not assignable to type 'number'.
✅ Kết luận thực dụng
  • tsx = chạy nhanh cho dev (auto-reload, không chờ biên dịch).
  • tsc --noEmit = typecheck — bắt lỗi type, không phát file. Đặt trong CI.
  • tsc = build — typecheck + phát JS ra dist/. Đặt trong deploy.

3. tsconfig.json — bảng khai thác đúng mức

tsconfig.json là "bảng điều khiển" cho tsc. File hiện tại của dự án bạn (đã verify chạy XANH):

elearning-backend/tsconfig.json — toàn bộ 
{
  "compilerOptions": {
    "target": "ES2022",           // JS phát ra theo chuẩn nào
    "module": "NodeNext",         // hệ module (ESM) theo Node hiện đại
    "moduleResolution": "NodeNext", // cách TS tìm file khi import
    "strict": true,              // chế độ nghiêm ngặt — bắt lỗi sớm
    "esModuleInterop": true,      // import CJS từ ESM mượt mà
    "experimentalDecorators": true, // bật decorators (bài 17)
    "skipLibCheck": true,          // bỏ check .d.ts của thư viện (nhanh hơn)
    "rootDir": "./src",            // gốc code — tái tạo cấu trúc trong dist/
    "outDir": "dist",               // nơi chứa JS đã biên dịch
    "types": ["node"]             // chỉ nạp type của node, không nạp hết mọi @types
  },
  "include": ["src"] // chỉ biên dịch thư mục src
}
CờQuyết định gìVì sao quan trọng
targetJS phát ra theo chuẩn ES nàoES2022 = chạy trên Node hiện đại, không cần transpile cũ
module / moduleResolutionESM hay CJS, cách tìm fileNodeNext khớp "type":"module" → import phải đủ đuôi .js
strictBật loạt kiểm tra nghiêm ngặtBắt lỗi type từ sớm — chuẩn senior
rootDir → outDirÁnh xạ src/ → dist/Giữ cấu trúc thư mục khi biên dịch
typesNạp type toàn cục nào["node"] giúp có process, Buffer… mà không kéo theo thư viện rác

💡 Vì sao phải biết flow này trước NestJS?

NestJS production không chạy bằng tsx mà bằng đúng flow này: nest build (bọc ngoài tsc) → chạy node dist/main.js. Hiểu tsc/dist ngay bây giờ thì sang Module 4 bạn chỉ việc "đổi tên lệnh", không bỡ ngỡ.

5. Thêm script cho gọn — bước đầu của "production-ready"

Chạy lệnh dài npx tsc rồi node dist/server.js mỗi lần là dễ quên. Chuẩn là đưa vào scripts của package.json (theo 12-Factor App: build là một bước tách bạch, lặp lại được):

package.json — thêm 3 script 
"scripts": {
  "dev": "tsx watch src/server.ts",   // dev: auto-reload
  "start": "tsx src/server.ts",        // dev: chạy 1 lần
  "typecheck": "tsc --noEmit",       // CI: chỉ kiểm tra type
  "build": "tsc",                     // production: biên dịch ra dist/
  "start:prod": "node dist/server.js"  // production: chạy JS thuần
}

Sau khi thêm, mọi việc gọn lại thành: npm run typecheck (kiểm tra), npm run build (biên dịch), npm run start:prod (chạy). Cùng một lệnh, chạy được ở mọi máy.

6. Nâng cao (senior) — 3 cờ bạn sẽ gặp tiếp
