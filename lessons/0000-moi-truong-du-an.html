Module 0 · Bài 00

Dựng môi trường + khung dự án e-learning chạy được

Máy của bạn có sẵn mọi công cụ — bài này biến chúng thành một dự án backend chạy thật và một database PostgreSQL.

⏱ ~30 phút · 🎯 Mục tiêu: server Node của bạn trả lời HTTP 200 + PostgreSQL chạy trong Docker, cả hai bật bằng 2 lệnh.

🌉 Bắc cầu từ cái bạn đã biết

Bạn đã cài Node, Docker, git trên máy (tôi đã kiểm tra trực tiếp). Bài này không dạy gì mới về lập trình — chỉ dàn cảnh sân khấu: đặt mọi thứ vào đúng chỗ, bật công tắc, nhìn đèn sáng. Từ bài sau trở đi mọi kiến thức sẽ bám vào dự án này, lớn dần thành e-learning hoàn chỉnh.

1. Tạo thư mục dự án

Toàn bộ hành trình của bạn nằm trong thư mục elearning-backend/ — dự án chính mà mỗi bài sau sẽ thêm vào. Chạy lệnh sau trong terminal (thư mục hiện tại đã là learn_fullstack):

bash 
# Tạo thư mục dự án và đi vào trong
mkdir elearning-backend && cd elearning-backend
💡 Vì sao có "sân tập" riêng?

Khi bạn quay lại sau 2 tuần, thư mục này chứa toàn bộ lịch sử dự án — mỗi bài là một mốc bạn nhìn thấy sản phẩm lớn dần. Không phải học xong mới làm: bài đầu tiên đã có thứ chạy được.

2. Khởi tạo dự án Node.js

npm init -y tạo file package.json — "giấy khai sinh" của dự án Node: tên, phiên bản, và đặc biệt là danh sách dependencies (các thư viện cần cài). Sau này mỗi package bạn cài đều ghi vào đây.

bash 
# Khởi tạo dự án với cấu hình mặc định (không hỏi gì thêm)
npm init -y

3. Cài trình chạy TypeScript (tsx)

Từ Module 3 bạn sẽ học TypeScript (TS) sâu. Ngay từ bây giờ, dự án dùng TS — tsx là trình chạy TS trực tiếp trên Node, không cần bước biên dịch riêng, kèm chế độ watch tự reload khi sửa file. Đây là công cụ phổ biến và ổn định cho dev hiện đại.

bash 
# Cài tsx làm dependency chính (chạy được cả lúc dev lẫn production)
npm install tsx

Theo tài liệu chính thức của tsx, tsx hỗ trợ chạy TypeScript và ESM trực tiếp, không cần cấu hình. Đã kiểm chứng với tsx 4.23.9 trên Node v20.19.3.

4. Cấu hình package.json — script chạy

Scripts trong package.json là "rút gọn lệnh": bạn gõ npm run dev thay vì cả chuỗi dài. Mở file package.json bằng editor và thay toàn bộ nội dung:

package.json 
{
  "name": "elearning-backend",
  "version": "1.0.0",
  "type": "module",          // dùng ESM (import/export) thay vì CommonJS (require)
  "scripts": {
    "dev": "tsx watch src/server.ts",  // chạy dev: tự reload khi sửa file
    "start": "tsx src/server.ts"       // chạy production-style: không watch
  },
  "dependencies": {
    "tsx": "^4.23.9"
  }
}
💡 Vì sao "type": "module"?

Node có 2 hệ thống module: CommonJS (require) và ESM (import). ESM là chuẩn hiện đại, được NestJS/TypeScript dùng. Khai báo "type": "module" giúp Node hiểu file .ts của bạn dùng cú pháp import. Bài 05 sẽ đào sâu vì sao.

5. Cài type definitions cho Node + tạo tsconfig

TypeScript cần biết "hình dạng" của thư viện gốc Node (như http, fs) để gợi ý đúng và báo lỗi sớm. Gói @types/node cung cấp đúng thứ đó — đây là loại lỗi mà chỉ verify trong thư mục sạch mới phát hiện ra:

bash 
# Cài type definitions cho Node — chỉ cần khi dev, không cần lúc chạy
npm install -D @types/node

Sau đó tạo file tsconfig.json — cấu hình cách TypeScript kiểm tra code của bạn:

bash — tạo file cấu hình TS 
cat > tsconfig.json << 'EOF'
{
  "compilerOptions": {
    "target": "ES2022",          // nhắm tới chuẩn ES2022 — đủ mới cho mọi tính năng hiện đại
    "module": "NodeNext",       // hệ thống module theo Node hiện đại
    "moduleResolution": "NodeNext", // cách TS tìm file khi import
    "strict": true,              // bật chế độ nghiêm ngặt — bắt lỗi sớm, chuẩn senior
    "esModuleInterop": true,    // import CJS từ ESM mượt mà
    "skipLibCheck": true,        // bỏ kiểm tra file .d.ts của thư viện (nhanh hơn)
    "outDir": "dist"            // nơi chứa code biên dịch (dùng sau này ở production)
  },
  "include": ["src"]           // chỉ kiểm tra code trong thư mục src
}
EOF

6. Viết server đầu tiên — Node thuần (chưa cần framework)

Tạo thư mục src và file server.ts. Đây là server HTTP thuần Node — không Express, không NestJS — để bạn thấy tận mắt nền tảng bên dưới mọi framework:

bash — tạo thư mục source 
mkdir src
src/server.ts 
import { createServer } from 'node:http'; // lấy hàm tạo web server từ module http của Node

// Tạo server: mỗi khi có request tới, hàm này được gọi
const server = createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('E-Learning API đang chạy! 🚀');
});

const PORT = 4000;      // cổng mặc định — đổi được khi cần
const HOST = '0.0.0.0'; // lắng nghe mọi kết nối, không chỉ localhost

// Bật server, in ra URL để mở trình duyệt
server.listen(PORT, HOST, () => {
  console.log(`✅ Server chạy tại http://localhost:${PORT}`);
});
💡 Vì sao bắt đầu bằng Node thuần?

Express và NestJS đều được xây trên chính node:http này. Khi bạn hiểu request/response/vòng đời ở tầng gốc, mọi khái niệm framework sau này ("middleware", "controller", "pipe") chỉ là lớp bọc quanh đúng thứ bạn đang thấy. Bài 04–08 sẽ đào sâu toàn bộ.

7. Chạy server — sanity check đầu tiên

Giờ bật máy. Lệnh này khởi động server và không tắt terminal (chạy nền):

bash 
npm run dev

Bạn sẽ thấy ✅ Server chạy tại http://localhost:4000. Mở trình duyệt tới http://localhost:4000 — bạn thấy dòng chữ "E-Learning API đang chạy! 🚀". Hoặc kiểm tra bằng lệnh (mở terminal mới):

bash — terminal thứ hai 
# Gửi request HTTP tới server. -s: im lặng, -o /dev/null: bỏ nội dung, -w: in status code
curl -s -o /dev/null -w "%{http_code}" http://localhost:4000

Kết quả phải là 200 — mã chuẩn nghĩa là "thành công". Đây là sanity check tối thiểu chứng minh cả bộ máy chạy.

✅ Đã kiểm chứng trên máy thật

Các bước 1–7 đã chạy XANH trong sandbox sạch: Node v20.19.3 + tsx 4.23.9, server trả HTTP 200 đúng nội dung. Bạn làm theo đúng thứ tự sẽ ra kết quả y hệt.

8. PostgreSQL qua Docker — database của dự án

Backend cần lưu dữ liệu. Chuẩn production cho database là chạy PostgreSQL. Thay vì cài native (máy bạn chưa có), ta chạy PostgreSQL trong Docker container — một "chiếc máy ảo siêu nhẹ" chứa đúng PostgreSQL, cô lập khỏi hệ điều hành. Cách này sạch, đồng nhất mọi máy, và đúng cách làm industry.

Theo tài liệu Docker Compose, file docker-compose.yml khai báo các container của dự án dưới dạng mã — cả nhóm đều dùng được, không cần cài thủ công.

Với server đang chạy ở terminal 1, mở terminal mới và tạo file docker-compose.yml:

docker-compose.yml 
# Khai báo container PostgreSQL cho dự án e-learning
services:
  postgres:
    image: postgres:16-alpine              # bản PostgreSQL 16, nhẹ (alpine)
    container_name: elearning-postgres      # tên container để dễ nhận diện
    environment:                           # biến môi trường cho PostgreSQL khởi tạo
      POSTGRES_USER: elearning              # tài khoản admin của database
      POSTGRES_PASSWORD: elearning_dev_password # mật khẩu — chỉ cho dev, bài sau học cách giấu
      POSTGRES_DB: elearning                # tên database mặc định
    ports:
      - "5432:5432"          # mở cổng 5432 của máy ra container 5432
    volumes:
      - pgdata:/var/lib/postgresql/data    # lưu data vào ổ "pgdata" — không mất khi tắt container

volumes:
  pgdata:                                   # khai báo ổ lưu trữ bền vững

9. Khởi động PostgreSQL và kiểm tra kết nối

Lệnh sau tải image (lần đầu), tạo container, và chạy nó nền:

bash 
# Dựng và chạy các container đã khai báo trong docker-compose.yml
docker compose up -d

Container tên elearning-postgres sẽ chạy. Kiểm tra nó sẵn sàng nhận kết nối:

bash — kiểm tra PostgreSQL bên trong container 
# Hỏi PostgreSQL "bạn sẵn sàng chưa?" bằng chính công cụ của nó
docker exec elearning-postgres pg_isready -U elearning

Kết quả mong đợi:

output 
/var/run/postgresql:5432 - accepting connections
💡 Vì sao PostgreSQL chạy trong Docker — không cài native?

So sánh: cài native là "một lần cho riêng máy này"; Docker là "mã nguồn cho mọi máy". Đồng nghiệp clone repo của bạn, gõ docker compose up -d, có ngay database y hệt — không cần đọc wiki 20 bước. Đây chính là tư duy infrastructure-as-code mà senior cần.

10. File .gitignore — không commit rác

node_modules/ (hàng nghìn file cài từ npm) và .env (bí mật) không bao giờ được đưa lên git. File .gitignore bảo git "kệ mấy thứ này":

.gitignore 
# Thư mục dependencies cài tự động từ npm — cài lại được bằng "npm install"
node_modules/

# Code biên dịch — sinh ra từ source, không cần commit
dist/

# Bí mật môi trường — bài 06+ sẽ dùng
.env
