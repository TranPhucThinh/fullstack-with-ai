HTTP server bằng Node thuần (http module)

Mổ xẻ node:http — hiểu req/res là đối tượng gì, vì sao createServer nhận 2 tham số, và các cách trả response.

⏱ ~50 phút · 🎯 Mục tiêu: giải thích được IncomingMessage vs ServerResponse, phân biệt res.write/res.end, và viết demo inspect request thật.

🌉 Bắc cầu từ cái bạn đã biết

Từ bài 02 bạn đã viết createServer((req, res) => ...) và dùng req.on('data'), res.writeHead, res.end. Nhưng req và res thực chất là gì? Vì sao req.on('data') hoạt động như stream? Bài này mổ xẻ node:http — tầng thấp nhất mà Express và NestJS đều nằm trên.

1. node:http — module nền tảng của mọi web server

node:http là module có sẵn trong Node (không cần cài npm). Theo Node.js docs — HTTP, nó cung cấp http.createServer([options][, requestListener]) — hàm tạo ra một http.Server.

Cú pháp createServer — tách bạch hai cách dùng 
import http from 'node:http'

// Cách 1 (viết gọn, bạn đang dùng): truyền thẳng requestListener
const server1 = http.createServer((req, res) => {
  res.end('Hello')
})

// Cách 2: server là EventEmitter — tự đăng ký sự kiện 'request'
const server2 = http.createServer()
server2.on('request', (req, res) => {
  res.end('Hello')
})
💡 Vì sao hay nhầm "2 cách"?

Theo Node.js Learn — Anatomy of an HTTP Transaction, cái hàm truyền vào createServer được gọi mỗi lần có request và nó chính là request handler. Thực ra http.Server là một EventEmitter: cách 1 chỉ là shorthand của cách 2 (tự thêm listener cho sự kiện 'request'). Hiểu điều này giúp bạn nhớ vì sao server hoạt động event-based — liên quan thẳng tới event loop bài 04.

2. req — đối tượng IncomingMessage (stream đọc)

Theo Node.js docs — IncomingMessage, req là một thể hiện của http.IncomingMessage, được tạo nội bộ bởi http.Server và truyền làm tham số đầu tiên. Quan trọng: nó extends stream.Readable — tức req là một stream đọc, đọc dữ liệu đến theo từng chunk qua sự kiện 'data'/'end'. Đây chính là lý do bài 03 phải gom body bằng req.on('data').

Thuộc tính/phương thứcÝ nghĩaVí dụ
req.methodHTTP method của request'GET', 'POST', 'DELETE'
req.urlĐường dẫn + query string (chưa phân rã)'/api/courses?id=1'
req.headersObject chứa toàn bộ header (thường lowercase){ host: 'localhost:4000', 'content-type': 'application/json' }
req.on('data'/'end')Stream Readable — đọc body theo chunkGom body POST

3. res — đối tượng ServerResponse (stream ghi)

Theo Node.js docs — ServerResponse, res là thể hiện của http.ServerResponse, được tạo nội bộ bởi HTTP server và truyền làm tham số thứ hai. Nó extends http.OutgoingMessage (một stream ghi writable) — bạn ghi dữ liệu vào nó và Node gửi đi qua socket.

Cách ghiÝ nghĩaKhi nào dùng
res.statusCode = 200Gán mã trạng tháiTrước khi gửi header
res.setHeader(name, value)Gán một headerGán Content-Type, Cache-Control...
res.writeHead(code, headers)Gán status + nhiều header trong một lầnViết gọn, hay dùng trong API
res.write(chunk)Ghi thêm một phần body (gọi nhiều lần được)Stream dữ liệu lớn
res.end(data?)Kết thúc response, có thể kèm mẩu body cuốiLuôn luôn phải gọi để kết thúc
⚠️ Quên res.end() — request treo vô hạn

Nếu bạn ghi body nhưng không gọi res.end(), Node sẽ không kết thúc response — client chờ mãi tới khi timeout. Đây là lỗi rất phổ biến của dev mới viết Node thuần. Luôn nhớ: res.end() là dấu chấm hết của response; nếu bạn gọi res.end() hai lần sẽ bị lỗi "write after end".

4. Thực hành — demo inspect request trên máy thật

Tạo 2 file trong thư mục demo/ (đã có từ bài 04-05). Đây là minh hoạ trực quan về request/response mà createServer đưa vào handler.

demo/inspect-http.mjs 
// File: demo/inspect-http.mjs
// Mổ xẻ req: in ra method, url, headers rồi trả response
import { createServer } from 'node:http'

// Mỗi request tới → Node gọi handler này với (req, res)
const server = createServer((req, res) => {
  console.log('=== REQUEST VỪA NHẬN ===')
  console.log('method :', req.method)        // GET/POST/...
  console.log('url    :', req.url)           // path + query, chưa phân rã
  console.log('headers:', req.headers)     // object chứa mọi header
  console.log('host   :', req.headers.host)

  // Trả response đơn giản — statusCode + header + end
  res.statusCode = 200
  res.setHeader('Content-Type', 'text/plain; charset=utf-8')
  res.end('Xin chào từ http module!')
})

server.listen(4010, () => {
  console.log('✅ Server chạy tại http://localhost:4010')
})
demo/response-options.mjs — phân biệt write vs end 
// File: demo/response-options.mjs
import { createServer } from 'node:http'

const server = createServer((req, res) => {
  // Cách tách bạch: gán status + header riêng
  res.statusCode = 404
  res.setHeader('Content-Type', 'text/plain; charset=utf-8')

  res.write('Phần 1 của body\n')   // write: ghi thêm — gọi nhiều lần được
  res.write('Phần 2 của body\n')
  res.end('Xong!')                  // end: KẾT THÚC response, kèm mẩu cuối
})
server.listen(4011, () => console.log('✅ http://localhost:4011'))
Terminal — chạy demo và quan sát 
# Từ thư mục elearning-backend/
cd demo
node inspect-http.mjs          # mở terminal riêng để chạy server
node response-options.mjs     # demo thứ 2 — dùng cổng 4011

# Ở terminal khác, gửi request:
curl 'http://localhost:4010/hello?x=1'
# Server in ra: method=GET, url=/hello?x=1, headers=..., host=localhost:4010

curl -i http://localhost:4011/
# → HTTP/1.1 404 Not Found, body: Phần 1 + Phần 2 + Xong!
✅ Đã kiểm chứng trên Node v24

Đã chạy thật: inspect-http.mjs in ra đúng method/url/headers khi curl; response-options.mjs trả HTTP 404 + 3 phần body (write, write, end). Với máy bạn (Node v24.16.0) kết quả giống hệt.
