TypeORM + PostgreSQL — entity ánh xạ bảng, repository thay SQL tay

Bài 22 `POST /courses` chỉ trả lại DTO. Giờ nối database thật: entity `CourseEntity` ánh xạ bảng `courses`, service dùng Repository để lưu/đọc — không viết SQL tay như bài 12.

⏱ ~45 phút · 🎯 Mục tiêu: giải thích được entity ↔ bảng, repository ↔ SQL, và vì sao `synchronize` chỉ dùng dev.

🌉 Bắc cầu từ bài 12 (pg) và bài 22 (DTO)

Bài 12 bạn viết SQL tay qua `pg.Pool`. Bài 22 bạn có DTO đã validate. Giờ TypeORM nối hai thứ: entity (class ánh xạ bảng) + repository (đối tượng thay cho câu SQL). Nest inject repository vào service qua DI — đúng tinh thần bài 21.

1. Entity — class ánh xạ bảng

src/nest/course.entity.ts — entity mới 
import { Column, CreateDateColumn, Entity, PrimaryGeneratedColumn } from 'typeorm'

// Entity: ánh xạ class -> bảng 'courses' trong PostgreSQL
@Entity('courses')
export class CourseEntity {
  @PrimaryGeneratedColumn() // id tự tăng (SERIAL)
  id!: number

  @Column({ type: 'varchar', length: 255 })
  title!: string

  @Column({ type: 'integer', default: 0 })
  price!: number

  @CreateDateColumn() // tự gán thời điểm tạo
  createdAt!: Date
}
💡 Entity khác DTO thế nào?

DTO mô tả dữ liệu vào (body client gửi). Entity mô tả dữ liệu lưu (bảng DB). DTO có thể thiếu `id`/`createdAt`; entity có đủ. Đừng nhầm hai thứ — đây là lỗi phổ biến của junior.

2. Kết nối TypeORM trong module

src/nest/app.module.ts — thêm TypeOrmModule 
import { Module } from '@nestjs/common'
import { TypeOrmModule } from '@nestjs/typeorm'
import { AppController } from './app.controller.js'
import { CoursesService } from './courses.service.js'
import { CourseEntity } from './course.entity.js'

@Module({
  imports: [
    // Kết nối PostgreSQL + đăng ký entity CourseEntity
    TypeOrmModule.forRoot({
      type: 'postgres',
      host: 'localhost',
      port: 5432,
      username: 'elearning',
      password: 'elearning_dev_password',
      database: 'elearning',
      entities: [CourseEntity],
      synchronize: true, // tự tạo bảng khi dev — production dùng migration (bài sau)
    }),
    // Đăng ký Repository cho DI
    TypeOrmModule.forFeature([CourseEntity]),
  ],
  controllers: [AppController],
  providers: [CoursesService],
})
export class AppModule {}
⚠️ `synchronize: true` chỉ dành cho dev

`synchronize` tự tạo/sửa bảng theo entity mỗi lần khởi động — tiện khi dev nhưng nguy hiểm ở production (có thể xóa cột, mất data). Production phải dùng migration (bài sau). Đây là điểm hay bị hỏi phỏng vấn.

3. Service dùng Repository

src/nest/courses.service.ts — thay mảng hằng bằng DB 
import { Injectable } from '@nestjs/common'
import { InjectRepository } from '@nestjs/typeorm'
import { Repository } from 'typeorm'
import { CourseEntity } from './course.entity.js'
import { CreateCourseDto } from './create-course.dto.js'

@Injectable()
export class CoursesService {
  // Inject Repository — TypeORM tự cung cấp cho entity CourseEntity
  constructor(
    @InjectRepository(CourseEntity)
    private readonly repo: Repository,
  ) {}

  findAll(): Promise {
    return this.repo.find() // SELECT * FROM courses
  }

  create(dto: CreateCourseDto): Promise {
    // repo.create() tạo instance entity (không lưu); repo.save() INSERT hoặc UPDATE
    const entity = this.repo.create(dto)
    return this.repo.save(entity)
  }
}
💡 Vì sao `repo.create(dto)` rồi mới `save()`?

`repo.create()` tạo instance entity từ plain object (DTO) — TypeORM biết field nào thuộc entity. `repo.save()` mới thực sự INSERT. Tách hai bước giúp bạn kiểm tra/đổi entity trước khi lưu. Có thể gọi `repo.save(dto)` trực tiếp nhưng mất kiểm soát.

4. Controller — không đổi nhiều

src/nest/app.controller.ts — service giờ trả Promise 
import { Body, Controller, Get, Post } from '@nestjs/common'
import { CreateCourseDto } from './create-course.dto.js'
import { CoursesService } from './courses.service.js'

@Controller()
export class AppController {
  constructor(private readonly coursesService: CoursesService) {}

  @Get()
  getRoot(): { message: string } {
    return { message: 'E-Learning NestJS đã chạy' }
  }

  @Get('courses')
  findAll() {
    return this.coursesService.findAll() // Promise — Nest tự await và trả JSON
  }

  // Body được ValidationPipe validate -> DTO đã hợp lệ -> service lưu vào DB
  @Post('courses')
  create(@Body() dto: CreateCourseDto) {
    return this.coursesService.create(dto)
  }
}
💡 Nest tự await Promise

Controller trả về `Promise` — Nest tự `await` và serialize thành JSON. Bạn không cần `async/await` trong controller nếu service đã trả Promise. Đây là điểm khác Express (phải tự `await` trong handler).

5. Thử thách triển khai

Đề bài

Từ code bài 22, nối TypeORM + PostgreSQL để `POST /courses` thực sự lưu vào bảng `courses`.

  • TC1: Tạo `src/nest/course.entity.ts` với `@Entity('courses')`, `id` (PrimaryGeneratedColumn), `title` (varchar 255), `price` (integer default 0), `createdAt` (CreateDateColumn).
  • TC2: `app.module.ts` thêm `TypeOrmModule.forRoot({...})` kết nối PostgreSQL (user `elearning`, db `elearning`) + `TypeOrmModule.forFeature([CourseEntity])`.
  • TC3: `courses.service.ts` inject `Repository` qua `@InjectRepository`, `findAll()` dùng `repo.find()`, `create(dto)` dùng `repo.create()` + `repo.save()`.
  • TC4: `app.controller.ts` gọi service (trả Promise).
  • TC5: POST tạo khóa → trả entity có `id` + `createdAt`; GET trả danh sách từ DB (không phải mảng hằng).

Definition of Done: POST 2 khóa → GET trả 2 khóa có `id` + `createdAt`; bạn tự giải thích vì sao `synchronize` không dùng ở production.

Hint ladder — chỉ mở khi kẹt thật

Hint 1 · Package đã cài sẵn

`typeorm@1.1.0` và `@nestjs/typeorm@11.0.3` đã có trong `package.json`. PostgreSQL đang chạy qua docker (user `elearning`, password `elearning_dev_password`, db `elearning`).

Hint 2 · Lỗi "no metadata for CourseEntity"

Quên đăng ký entity trong `entities: [CourseEntity]` của `forRoot` hoặc quên `forFeature([CourseEntity])`. Cả hai đều cần.

🎤 Góc phỏng vấn — "TypeORM là gì?"

Trả lời gọn: TypeORM là ORM (Object-Relational Mapping) — ánh xạ class (entity) sang bảng, method (repository) sang SQL. Nest tích hợp qua `TypeOrmModule.forRoot()` (kết nối) + `forFeature()` (đăng ký repository cho DI). Ưu điểm: không viết SQL tay, type-safe, quản lý migration.
