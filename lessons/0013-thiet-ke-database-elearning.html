Thiết kế database e-learning — ERD, bảng users/courses

Thiết kế bảng có quan hệ đúng (khóa ngoại, 1-nhiều, nhiều-nhiều) cho e-learning — từ vấn đề thực tế tới ERD rồi SQL thật.

⏱ ~90 phút · 🎯 Mục tiêu: vẽ được ERD e-learning (users, courses, enrollments), hiểu quan hệ & khóa ngoại, tạo bảng + JOIN thật trong PostgreSQL.

🌉 Bắc cầu từ cái bạn đã biết

Bài 12 bạn đã có bảng users đơn lẻ và CRUD. Nhưng e-learning thật không chỉ có users — còn courses (khóa học) và enrollments (ai đăng ký khóa nào). Bài này giải bài toán: thiết kế các bảng liên quan nhau như thế nào để không trùng lặp, không sai lệch dữ liệu, và truy vấn được "user nào học khóa nào".

1. Vấn đề khi lưu mọi thứ trong 1 bảng

Giả sử chỉ có một bảng lưu mọi thứ — học viên + khóa học họ đăng ký:

user_iduser_nameuser_emailcourse_titlecourse_price
1Ana@ex.comNestJS cơ bản500000
1Ana@ex.comDesign Pattern800000
2Binhb@ex.comNestJS cơ bản500000
2Binhb@ex.comSQL Master700000

Các vấn đề (gọi là redundancy / update anomaly):

  • Trùng lặp: "An" xuất hiện 2 lần, "NestJS cơ bản" xuất hiện 2 lần — tốn dung lượng, dễ sai khi sửa.
  • Cập nhật không nhất quán: đổi giá khóa học 500000 phải sửa nhiều dòng, lỡ quên 1 dòng là data sai.
  • Khó mở rộng: muốn thêm trường "khóa học có bao nhiêu bài giảng" phải đụng bảng users.
💡 Giải pháp: tách bảng (normalization)

Thay vì một bảng khổng lồ, ta tách thành users (thông tin người) và courses (thông tin khóa) — mỗi thứ lưu một lần — rồi dùng bảng trung gian nối quan hệ. Đây là ý tưởng cốt lõi của database normalization: mỗi dữ liệu lưu đúng một nơi, tránh trùng lặp và dị thường.

2. Ba kiểu quan hệ

Theo PostgreSQL docs và lý thuyết quan hệ, có 3 kiểu quan hệ chính giữa bảng:

Quan hệÝ nghĩaVí dụ e-learningBiểu diễn
1–1 (one-to-one)1 dòng bảng A khớp đúng 1 dòng bảng Buser ↔ profile chi tiếtKhóa ngoại + UNIQUE
1–nhiều (one-to-many)1 dòng bảng A có nhiều dòng bảng B1 course có nhiều lessonsKhóa ngoại ở bảng "nhiều"
nhiều–nhiều (many-to-many)Nhiều dòng A ↔ nhiều dòng Buser học nhiều courses, course có nhiều usersBảng trung gian (junction)

Trong e-learning, quan hệ quan trọng nhất là user ↔ course là nhiều-nhiều: một user có thể mua nhiều khóa, một khóa có thể có nhiều học viên. Nhiều-nhiều không biểu diễn trực tiếp được bằng khóa ngoại đơn — cần bảng trung gian enrollments.

3. Khóa ngoại (FOREIGN KEY) — dây nối giữa bảng

Theo PostgreSQL docs, khóa ngoại là constraint đảm bảo "the values in a column must match the values appearing in some row of another table" — cột trong bảng này phải tồn tại trong bảng kia. Nó chính là thứ ép database giữ đúng quan hệ, không cho insert dữ liệu lỏng lẻo.

Cú pháp khóa ngoại 
CREATE TABLE enrollments (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  course_id INTEGER NOT NULL REFERENCES courses(id),
  enrolled_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
💡 Vì sao khóa ngoại quan trọng?

Nếu không có REFERENCES, bạn có thể insert enrollment với user_id=999 (không tồn tại) — data rác. Khóa ngoại khiến database tự chặn: lỗi ngay khi cố vi phạm. Đây là tầng bảo vệ cuối cùng, không phụ thuộc code ứng dụng.

4. ERD cho e-learning

ERD (Entity-Relationship Diagram) là bản vẽ các bảng và quan hệ — đọc trước khi viết SQL để hình dung rõ. ERD tối giản cho e-learning:

🗺️ ERD — users ↔ courses qua enrollments (nhiều-nhiều)
users 1 ──── * enrollments * ──── 1 courses
  id  │              │              │  id
  email                │              │  title
  name                 │              │  price
                       │
                       └── user_id, course_id, enrolled_at
BảngVai tròCột chính
usersNgười dùng (học viên/giảng viên/admin)id, email (UNIQUE), name, role
coursesKhóa họcid, title, price, description
enrollmentsBảng trung gian: user đăng ký courseid, user_id FK, course_id FK, enrolled_at

Ký hiệu 1 ──── * nghĩa là "một users có nhiều enrollments" và * ──── 1 nghĩa là "nhiều enrollments thuộc một course". enrollments là junction table phá vỡ quan hệ nhiều-nhiều thành hai quan hệ 1-nhiều.

5. Tạo bảng thật trong PostgreSQL

Bảng users đã có từ bài 12. Giờ thêm courses và enrollments bằng SQL thật:

Terminal — SQL tạo bảng courses + enrollments 
docker exec -it elearning-postgres psql -U elearning -d elearning -c "CREATE TABLE courses (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  price INTEGER NOT NULL DEFAULT 0 CHECK (price >= 0),
  description TEXT
);"

docker exec -it elearning-postgres psql -U elearning -d elearning -c "CREATE TABLE enrollments (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  course_id INTEGER NOT NULL REFERENCES courses(id),
  enrolled_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, course_id)
);"
ConstraintÝ nghĩa
CHECK (price >= 0)Giá không âm — database tự chặn
REFERENCES users(id)user_id phải tồn tại trong users
UNIQUE (user_id, course_id)Một user chỉ đăng ký một khóa 1 lần — chống trùng enrollment

Theo PostgreSQL docs, CHECK giới hạn giá trị cột (vd giá không âm); UNIQUE (a, b) là unique trên tổ hợp cột — rất hữu ích cho bảng trung gian.

⚠️ Trước khi chạy: users phải có sẵn

Vì enrollments.user_id tham chiếu tới users(id), bạn phải có bảng users (đã tạo bài 12) và có dữ liệu users trước khi insert enrollment. Nếu bảng users chưa có, chạy lại lệnh CREATE TABLE users ở bài 12.

6. INSERT dữ liệu quan hệ

Chèn dữ liệu thật để thấy quan hệ hoạt động:

Terminal — chèn courses + enrollments 
docker exec -it elearning-postgres psql -U elearning -d elearning -c "INSERT INTO courses (title, price) VALUES ('NestJS cơ bản', 500000), ('Design Pattern', 800000);"

# Giả sử user id=1 (An) đăng ký khóa 1, user id=2 đăng ký khóa 1 và 2
docker exec -it elearning-postgres psql -U elearning -d elearning -c "INSERT INTO enrollments (user_id, course_id) VALUES (1, 1), (2, 1), (2, 2);"

Thử vi phạm khóa ngoại để thấy database chặn:

Terminal — vi phạm khóa ngoại 
# user_id=999 không tồn tại -> database từ chối (lỗi foreign key)
docker exec -it elearning-postgres psql -U elearning -d elearning -c "INSERT INTO enrollments (user_id, course_id) VALUES (999, 1);"
# ERROR: insert or update on table "enrollments" violates foreign key constraint

7. JOIN — gộp bảng để trả câu hỏi nghiệp vụ

Dữ liệu nằm rải ở 3 bảng. JOIN là cách gộp chúng lại theo quan hệ. Câu hỏi: "An đang học những khóa nào?" — cần nối users → enrollments → courses:

Terminal — JOIN 3 bảng 
docker exec -it elearning-postgres psql -U elearning -d elearning -c "SELECT users.name, courses.title
FROM users
JOIN enrollments ON enrollments.user_id = users.id
JOIN courses ON courses.id = enrollments.course_id
WHERE users.id = 1;"
💡 Cách đọc JOIN

FROM users → đi từ bảng người. JOIN enrollments ON enrollments.user_id = users.id → nối với enrollments nơi khóa ngoại khớp. JOIN courses ON ... → nối tiếp. Kết quả là danh sách các cặp (user, course) qua enrollments — đúng nghiệp vụ "user đăng ký khóa nào".

8. Tổng kết — bạn vừa đạt được

  • Nhận ra vấn đề trùng lặp/dị thường khi lưu một bảng
  • Phân biệt 3 quan hệ: 1-1, 1-nhiều, nhiều-nhiều
  • Hiểu khóa ngoại (REFERENCES) — database tự chặn dữ liệu lỏng lẻo
  • Vẽ ERD e-learning: users ↔ enrollments ↔ courses
  • Tạo bảng thật (CHECK, UNIQUE tổ hợp) và truy vấn bằng JOIN
