3. Thêm CRUD courses + enrollments vào server.ts

Bạn đã có users (bài 12) + auth (bài 14) trong src/server.ts. Giờ thêm 3 route mới để hoàn thiện nghiệp vụ: tạo khóa, đăng ký khóa, xem khóa của mình. Đây là phần mới của bài 15 — dùng middleware auth đã có và bảng đã tạo ở bài 13.

src/server.ts — thêm route courses (cần auth) 
// GET /api/courses — danh sách khóa học (public)
app.get('/api/courses', async (req: Request, res: Response) => {
  const { rows } = await pool.query('SELECT * FROM courses ORDER BY id')
  res.json(rows)
})

// POST /api/courses — tạo khóa (CHỈ user đăng nhập)
app.post('/api/courses', auth, async (req: Request, res: Response) => {
  const { title, price, description } = req.body ?? {}
  if (!title) {
    res.status(400).json({ error: 'title là bắt buộc' })
    return
  }
  const { rows } = await pool.query(
    'INSERT INTO courses (title, price, description) VALUES ($1, $2, $3) RETURNING *',
    [title, price ?? 0, description ?? null],
  )
  res.status(201).json(rows[0])
})
💡 Vì sao POST /api/courses cần auth?

Chỉ người dùng đã đăng nhập mới được tạo khóa. Middleware auth (bài 14) đặt trước handler — không có token hợp lệ → 401, không tới được code tạo khóa. Đây là discipline: route nhạy cảm luôn được bảo vệ. (Sau này Module 5 sẽ phân quyền admin/teacher/student — ai được tạo khóa.)

src/server.ts — thêm route enrollments + me/courses (cần auth) 
// POST /api/enrollments — đăng ký khóa (CHỈ user đăng nhập)
app.post('/api/enrollments', auth, async (req: Request, res: Response) => {
  const { course_id } = req.body ?? {}
  if (!course_id) {
    res.status(400).json({ error: 'course_id là bắt buộc' })
    return
  }
  try {
    const { rows } = await pool.query(
      'INSERT INTO enrollments (user_id, course_id) VALUES ($1, $2) RETURNING *',
      [req.userId, course_id],
    )
    res.status(201).json(rows[0])
  } catch (e: any) {
    if (e.code === '23505') { // UNIQUE (user_id, course_id)
      res.status(409).json({ error: 'Đã đăng ký khóa này rồi' })
      return
    }
    if (e.code === '23503') { // khóa ngoại
      res.status(400).json({ error: 'Khóa học không tồn tại' })
      return
    }
    throw e
  }
})

// GET /api/me/courses — khóa học của tôi (JOIN enrollments + courses)
app.get('/api/me/courses', auth, async (req: Request, res: Response) => {
  const { rows } = await pool.query(
    `SELECT c.id, c.title, e.enrolled_at
     FROM enrollments e JOIN courses c ON c.id = e.course_id
     WHERE e.user_id = $1 ORDER BY e.enrolled_at`,
    [req.userId],
  )
  res.json(rows)
})
💡 JOIN "khóa của tôi" — áp dụng bài 13

Bài 13 bạn đã học JOIN để trả lời "user nào học khóa nào". Giờ áp dụng vào API: FROM enrollments e JOIN courses c ON c.id = e.course_id WHERE e.user_id = $1 — JOIN enrollments với courses qua khóa ngoại, lọc theo user đăng nhập lấy từ token (req.userId). Đây là nơi toàn bộ kiến thức bài 12-13-14 hội tụ.

⚠️ Bắt lỗi 23503 — khóa ngoại không tồn tại

Khi enroll course_id không có trong bảng courses, PostgreSQL ném lỗi 23503 (foreign key violation). Bắt và trả 400. Cùng với 23505 (trùng enrollment) → 409 ở bài 14, giờ bạn đã xử lý được đầy đủ lỗi database có chủ đích — kỹ năng senior.

4. Chạy và test toàn bộ flow

Chạy server rồi test đủ quy trình: đăng ký → đăng nhập → tạo khóa → đăng ký khóa → xem khóa của mình. (Đã verify XANH trên máy thật.)

Terminal 1 — chạy server 
npm run dev
Terminal 2 — curl toàn bộ flow 
# 1. Đăng ký → 201 + token
curl -X POST http://localhost:4000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"hocvien@ex.com","name":"Hoc Vien","password":"secret123"}'

# 2. Đăng nhập → lấy token (dán vào biến TOKEN)
TOKEN=$(curl -s -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"hocvien@ex.com","password":"secret123"}' \
  | node -e "process.stdin.on('data',d=>console.log(JSON.parse(d).token))")

# 3. Xem danh sách khóa (public)
curl -s http://localhost:4000/api/courses

# 4. Tạo khóa (cần token) → 201
curl -X POST http://localhost:4000/api/courses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"title":"Express tong ket","price":400000}'

# 5. Tạo khóa KHÔNG token → 401
curl -X POST http://localhost:4000/api/courses \
  -H "Content-Type: application/json" \
  -d '{"title":"Bi chan"}'

# 6. Đăng ký khóa id=1 (cần token) → 201
curl -X POST http://localhost:4000/api/enrollments \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"course_id":1}'

# 7. Xem khóa của tôi (JOIN) → trả khóa đã đăng ký
curl -s http://localhost:4000/api/me/courses \
  -H "Authorization: Bearer $TOKEN"

Đã chạy thật: register → 201 + token; login → token; GET /api/courses trả 2 khóa; POST /api/courses có token → 201 {id:3, title:"Express tong ket", ...}; POST không token → 401 {"error":"Thiếu token"}; POST /api/enrollments → 201; GET /api/me/courses → trả khóa đã đăng ký (vd "NestJS cơ bản"). 6. Câu hỏi tư duy (bắc cầu sang Module 3 — TypeScript)

Bạn đã build được API Express hoàn chỉnh nối PostgreSQL. Nhưng đối chiếu lại, type của bạn phần lớn dùng any (req.body, error...) — viết nhiều route thì dễ sai. NestJS (mục tiêu) xây trên TypeScript để type an toàn, đặc biệt decorators là nền tảng DI.
