DTO · ValidationPipe · class-validator — xác thực dữ liệu ở đúng tầng

Bài 21 controller nhận body nhưng chưa kiểm tra. Giờ thêm CreateCourseDto + ValidationPipe để Nest tự validate body trước khi tới controller — không còn if/else thủ công.

⏱ ~40 phút · 🎯 Mục tiêu: giải thích được vì sao DTO + pipe là cách chuẩn, và vì sao whitelist chống mass-assignment.

🌉 Bắc cầu từ bài 21

Bài 21 bạn đã thấy Nest tự inject service qua constructor. Giờ thêm một khái niệm nữa: pipe — một bước xử lý dữ liệu trước khi nó tới controller. Nest có sẵn ValidationPipe dùng class-validator để kiểm tra body theo DTO bạn khai báo.

1. Vì sao không tự if/else trong controller?

Ở Express (bài 12–15) bạn tự viết if (!title) return 400 trong handler. Với Nest, việc đó nên tách ra: controller chỉ nhận dữ liệu đã hợp lệ. Lý do:

  • DRY: cùng một DTO dùng lại cho nhiều route (vd tạo + sửa khóa học).
  • Đúng tầng: controller lo routing, pipe lo validation — mỗi thứ một việc.
  • Chống mass-assignment: whitelist tự loại field lạ client gửi lên (vd hack).

Theo tài liệu Pipes của NestJS, pipe có hai việc: transformation (biến đổi dữ liệu) và validation (kiểm tra). ValidationPipe làm cả hai: chuyển body thành instance của DTO rồi validate bằng decorators.

2. DTO — mô tả hình dạng body

src/nest/create-course.dto.ts — DTO mới 
import { IsNotEmpty, IsNumber, IsOptional, IsString, Max, Min } from 'class-validator'

// DTO: mô tả hình dạng body client gửi lên, kèm validator decorators
export class CreateCourseDto {
  @IsString()
  @IsNotEmpty()
  // ! vì DTO được ValidationPipe gán giá trị, không cần khởi tạo constructor
  title!: string

  @IsOptional() // cho phép bỏ qua field này
  @IsNumber()
  @Min(0)
  @Max(100_000_000)
  price?: number
}
💡 Vì sao dùng class thay vì interface?

Interface chỉ tồn tại lúc compile — bị xóa khi build. class-validator cần decorators để biết rule, mà decorators chỉ hoạt động trên class. Vì vậy DTO phải là class, không phải interface.

3. Bật ValidationPipe toàn cục

src/nest/main.ts — thêm global pipe 
import 'reflect-metadata'
import { ValidationPipe } from '@nestjs/common'
import { NestFactory } from '@nestjs/core'
import { AppModule } from './app.module.js'

async function bootstrap() {
  const app = await NestFactory.create(AppModule)
  // Global pipe: validate mọi body bằng class-validator trước khi tới controller
  app.useGlobalPipes(new ValidationPipe({ whitelist: true }))
  await app.listen(3000)
  console.log('NestJS: http://localhost:3000')
}

bootstrap().catch((error: unknown) => {
  console.error(error)
  process.exitCode = 1
})
⚠️ whitelist: true — chống mass-assignment

Khi bật, ValidationPipe tự loại bỏ mọi field không khai báo trong DTO trước khi tới controller. Nếu không bật, client có thể gửi field lạ (vd hack) và nó lọt vào body — nguy hiểm khi sau này bạn thêm field nhạy cảm (vd isAdmin).

4. Controller dùng DTO

src/nest/app.controller.ts — thêm POST /courses 
import { Body, Controller, Get, Post } from '@nestjs/common'
import { CoursesService } from './courses.service.js'
import { CreateCourseDto } from './create-course.dto.js'

@Controller()
export class AppController {
  constructor(private readonly coursesService: CoursesService) {}

  @Get()
  getRoot(): { message: string } {
    return { message: 'E-Learning NestJS đã chạy' }
  }

  @Get('courses')
  getCourses() {
    return this.coursesService.findAll()
  }

  // Body được ValidationPipe tự chuyển thành instance CreateCourseDto và validate
  @Post('courses')
  createCourse(@Body() dto: CreateCourseDto) {
    return dto // tạm trả lại để thấy dữ liệu đã được validate + whitelist
  }
}

Đề bài

  • TC2: main.ts bật app.useGlobalPipes(new ValidationPipe({ whitelist: true })).
  • TC3: AppController thêm POST /courses nhận @Body() dto: CreateCourseDto.

Definition of Done: 4 case curl đúng như mô tả; bạn tự giải thích vì sao DTO phải là class chứ không phải interface.

Hint ladder — chỉ mở khi kẹt thật

Hint 1 · Package đã cài sẵn

class-validator@0.15.1 và class-transformer@0.5.1 đã có trong package.json. Nếu clone máy sạch, chạy npm install là đủ.

Hint 2 · Lỗi strict "no initializer"

Khi khai title: string mà không gán, TS strict báo lỗi. Thêm ! (definite assignment assertion): title!: string — vì ValidationPipe sẽ gán giá trị, không cần khởi tạo constructor.
