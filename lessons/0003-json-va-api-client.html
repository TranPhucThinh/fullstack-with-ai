JSON & API client (curl/Postman)

Làm bạn với JSON — định dạng trao đổi dữ liệu của mọi API — và gọi API như một người chuyên nghiệp.

⏱ ~45 phút · 🎯 Mục tiêu: server của bạn nhận POST tạo khóa học mới qua JSON body, và bạn biết dùng curl + Postman để test API có tổ chức.

🌉 Bắc cầu từ cái bạn đã biết

Bài 02 server trả JSON qua GET /api/courses. Nhưng mới chỉ có đọc. Một e-learning platform cần tạo khóa học mới — client gửi JSON lên server, server nhận và xử lý. Đó là lúc bạn cần hiểu JSON sâu hơn và biết dùng công cụ gọi API ngoài curl.

1. JSON là gì — cấu trúc, kiểu dữ liệu

JSON (JavaScript Object Notation) là định dạng văn bản nhẹ để trao đổi dữ liệu, dễ đọc với người và dễ parse với máy. Theo MDN — JSON, nó là "định dạng tuần tự hóa" — chuyển object trong bộ nhớ thành chuỗi để gửi qua mạng.

JSON có 4 kiểu cơ bản:

KiểuVí dụGhi chú
string"NestJS cơ bản"Luôn trong dấu nháy kép ", không dùng nháy đơn
number500000Số nguyên hoặc thập phân, không có dấu nháy
booleantrue / falseChữ thường, không nháy
nullnullGiá trị rỗng, không nháy

JSON có 2 cấu trúc lồng ghép:

  • Object {...} — cặp key-value, key là string trong nháy kép
  • Array [...] — danh sách có thứ tự, có thể chứa object lồng nhau
JSON — dữ liệu mẫu một khóa học 
{
  "id": 1,
  "title": "NestJS cơ bản",
  "price": 500000,
  "published": true,
  "tags": ["nestjs", "backend"],
  "instructor": null
}
💡 JSON khác JavaScript object thế nào?

JS object có thể có key không nháy ({name: "A"}), có undefined, function, Date. JSON thì chỉ string, number, boolean, null, object, array. Key luôn trong nháy kép. Đây là thiết kế cố ý: JSON là định dạng trung gian giữa các ngôn ngữ, không phải tính năng của riêng JS.

2. JSON trong HTTP — request body & response body

Khi client gửi dữ liệu lên server (POST/PUT), dữ liệu đó nằm trong request body. Server cần biết body là JSON để parse đúng — header Content-Type: application/json làm nhiệm vụ đó.

Quy trình gửi JSON qua HTTP:

  1. Client tạo object JS → JSON.stringify(obj) → chuỗi JSON
  2. Gửi kèm header Content-Type: application/json
  3. Server đọc body → JSON.parse(rawBody) → object JS
  4. Server xử lý, trả về JSON response

Theo MDN — Content-Type, application/json là media type chuẩn của JSON.

3. Thực hành — thêm POST /api/courses vào server

Mở elearning-backend/src/server.ts, thêm route POST vào routing block. Server cần đọc body từ request (Node thuần không làm việc này tự động — phải gom chunk).

src/server.ts — thêm routing POST 
// Đặt KHỐI NÀY trước 2 route GET, sau khai báo courses array

if (req.method === 'POST' && path === '/api/courses') {
  // Gom body từ stream — Node http không tự parse body
  let body = ''
  req.on('data', (chunk) => { body += chunk }) // gom từng mảnh dữ liệu
  req.on('end', () => {
    const data = JSON.parse(body) // parse chuỗi JSON thành object

    // Tạo id mới: max id hiện có + 1
    const newId = courses.length > 0
      ? Math.max(...courses.map(c => c.id)) + 1
      : 1

    const course = { id: newId, title: data.title, price: data.price }
    courses.push(course) // thêm vào mảng (trong bộ nhớ — bài 12 mới có DB)

    res.writeHead(201, { 'Content-Type': 'application/json; charset=utf-8' })
    res.end(JSON.stringify(course)) // trả về course vừa tạo
  })
  return
}
⚠️ Express làm việc này tự động

Bạn thấy phải gom body thủ công bằng req.on('data') + req.on('end')? Đây là lý do vì sao Express có express.json() middleware — nó làm việc này cho bạn. Nhưng bạn cần thấy "gốc" trước để hiểu Express giải quyết bài toán gì.

4. Dùng curl với JSON body

Curl có thể gửi request với -X POST (method), -H (header), -d (data body):

Terminal — gửi POST tạo khóa học mới 
curl -X POST http://localhost:4000/api/courses \
  -H "Content-Type: application/json" \
  -d '{"title":"SQL cơ bản","price":300000}'

Kết quả mong đợi — server trả JSON + HTTP 201:

Output 
{"id":3,"title":"SQL cơ bản","price":300000}

Các flag curl hay dùng với API:

FlagÝ nghĩaVí dụ
-XPhương thức HTTP-X POST
-HHeader-H "Content-Type: application/json"
-dBody dữ liệu-d '{"key":"value"}'
-vVerbose — xem request/response đầy đủ-v
-iIn response headers-i
✅ Mẹo: curl với pipe + jq

Nếu bạn có jq (brew install jq), pipe output qua jq để xem JSON đẹp hơn: curl -s http://localhost:4000/api/courses | jq

5. API client — Postman / Insomnia

curl rất mạnh nhưng mỗi request phải gõ lại. API client cho phép lưu bộ sưu tập request, tổ chức thành collection, share với team.

Hai công cụ phổ biến:

  • Postman — phổ biến nhất, nhiều tính năng (environment, script, test automation)
  • Insomnia — nhẹ hơn, UI sạch, hỗ trợ GraphQL

Dùng Postman/Insomnia, bạn tạo request:

  1. Method: POST
  2. URL: http://localhost:4000/api/courses
  3. Headers: Content-Type: application/json
  4. Body → raw → JSON → {"title":"Design Pattern","price":700000}
  5. Send → thấy response 201 + JSON
💡 Vì sao cần cả curl lẫn API client?

Curl nhanh cho một lần test, dễ copy vào tài liệu/hướng dẫn. API client cho workflow test có tổ chức, lưu lại để test regression. Senior biết cả hai — và chọn đúng công cụ cho đúng việc.

6. Sanity check — chạy và kiểm tra

Sau khi sửa server.ts, chạy lại server và kiểm tra:

Terminal — full test suite 
# 1. POST — tạo khóa học mới
curl -s -X POST http://localhost:4000/api/courses \
  -H "Content-Type: application/json" \
  -d '{"title":"SQL cơ bản","price":300000}'
# → {"id":3,"title":"SQL cơ bản","price":300000} + HTTP 201

# 2. GET — kiểm tra danh sách có course mới
curl -s http://localhost:4000/api/courses
# → 3 courses, gồm course id=3

# 3. POST — body không hợp lệ (thiếu title)
curl -s -X POST http://localhost:4000/api/courses \
  -H "Content-Type: application/json" \
  -d '{"price":100000}'
# → {"id":4,"title":undefined,"price":100000} — lỗi: chưa validate
⚠️ Bug cố ý — không validate

Bạn thấy test 3: gửi thiếu title, server vẫn tạo course với title: undefined. Đây là lỗi thiếu validation — server không kiểm tra body trước khi dùng. Express/NestJS có cơ chế validate (ví dụ: class-validator) — nhưng bài này nhấn mạnh: JSON.parse không đảm bảo dữ liệu đúng. Senior phải validate dữ liệu đầu vào.
