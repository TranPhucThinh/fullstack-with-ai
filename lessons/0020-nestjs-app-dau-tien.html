NestJS app đầu tiên: container bắt đầu từ đâu?

Bạn đã tự viết DI container ở bài 19. Bây giờ chuyển sang framework thật: dựng một NestJS app tối thiểu và lần theo đúng đường đi main.ts → AppModule → AppController.

⏱ ~35 phút · 🎯 Một mục tiêu: giải thích được Nest bootstrap một dependency graph từ root module như thế nào.

🌉 Bắc cầu từ container mini của bạn

Bài 19, bạn gọi container.register('courseService', factory) rồi resolve(). NestJS cũng cần một nơi đăng ký và một điểm bắt đầu resolve. Khác biệt là Nest dùng class + decorator metadata: @Module() khai báo graph, còn NestFactory.create(AppModule) yêu cầu container dựng graph ấy.

1. NestJS không chỉ là “Express có decorator”

Express bắt đầu từ một object app, rồi bạn tự nối middleware và route. Nest bắt đầu từ một root module. Framework đọc metadata của module, tạo application context, khởi tạo controller/provider đã đăng ký, sau đó gắn route lên HTTP adapter.

💡 Root module là “composition root”

AppModule không chứa nghiệp vụ. Nó mô tả ứng dụng được ghép từ những thành phần nào. Theo NestJS Modules, mọi ứng dụng có ít nhất một root module; Nest dùng nó làm điểm bắt đầu dựng application graph. Đây là nơi nối hệ thống, không phải nơi xử lý request.

2. Đọc luồng bootstrap trước khi viết

  1. Node chạy src/nest/main.ts.
  2. NestFactory.create(AppModule) tạo application context và đưa AppModule
  3. Container đọc @Module({ controllers: [AppController] }), tạo một instance AppController.
  4. @Controller() + @Get() tạo route GET /.
  5. listen(3000) mở HTTP server; request đi tới method controller và kết quả object được trả thành JSON.

Hint 3 · Lời giải tham khảo đầy đủ

Chỉ đối chiếu sau khi đã tự thử. Import local giữ đuôi .js vì project đang dùng ESM + NodeNext.

src/nest/app.controller.ts 
import { Controller, Get } from '@nestjs/common'

// Prefix rỗng: controller nhận request tại đường dẫn gốc /
@Controller()
export class AppController {
  // GET / được ánh xạ vào method này bằng metadata
  @Get()
  getRoot(): { message: string } {
    return { message: 'E-Learning NestJS đã chạy' }
  }
}
src/nest/app.module.ts 
import { Module } from '@nestjs/common'
import { AppController } from './app.controller.js'

// Root module: khai báo node đầu tiên trong application graph
@Module({
  controllers: [AppController],
})
export class AppModule {}
src/nest/main.ts 
import 'reflect-metadata'
import { NestFactory } from '@nestjs/core'
import { AppModule } from './app.module.js'

// Composition root: container bắt đầu dựng graph từ AppModule
async function bootstrap() {
  const app = await NestFactory.create(AppModule)
  await app.listen(3000)
  console.log('NestJS: http://localhost:3000')
}

// Bootstrap lỗi phải làm process thất bại thay vì im lặng
bootstrap().catch((error: unknown) => {
  console.error(error)
  process.exitCode = 1
})

🎤 Góc phỏng vấn

“NestJS module dùng để làm gì?” — trả lời gọn: module là ranh giới tổ chức và composition unit; metadata của nó khai báo controller/provider/import/export, còn root module là điểm Nest bắt đầu dựng dependency graph. Module không nên chứa logic nghiệp vụ.

✅ Khi làm xong, gửi gì để review?
  • Ba file trong src/nest/ và phần scripts của package.json.
  • Output thật của curl http://localhost:3000/.
  • Một câu tự giải thích: tại sao chỉ có decorator là chưa đủ, controller vẫn phải nằm trong module?

Mình sẽ review 5 trục: đúng graph · đúng boundary · type safety · khả năng chẩn đoán lỗi · mức hiểu bản chất.
