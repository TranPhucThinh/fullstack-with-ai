TypeScript cơ bản — type, interface, generics

Học TypeScript từ nền tảng: type alias, interface, union, generics — thứ NestJS xây trên đó, và là cầu nối để dự án e-learning type an toàn hơn.

🌉 Bắc cầu từ cái bạn đã biết

Bài 15 bạn đã build API Express hoàn chỉnh, nhưng dùng nhiều any (req.body, error...) — viết nhiều route dễ sai. Bài 16 mở Module 3: TypeScript thêm type an toàn vào JavaScript. Bạn đã thấy TS hoạt động (tsx, tsconfig, typecheck) từ bài 00 — giờ học bản chất: type, interface, generics, là nền để hiểu NestJS (decorators, DI) ở Module 4.

1. Vì sao TypeScript? — bắt lỗi type lúc compile

JavaScript không có type: req.body.title có thể là undefined, number, hay bất cứ thứ gì — lỗi chỉ lộ ra lúc chạy. TypeScript thêm type annotation để trình biên dịch (tsc) bắt lỗi trước khi chạy. Theo TypeScript docs: "TypeScript is a strongly typed programming language that builds on JavaScript, giving you better tooling at any scale."

💡 Vì sao quan trọng với bạn?

Bài 14 bạn đã tự fix lỗi type userId bằng express.d.ts — đó chính là TS. NestJS (mục tiêu) xây hoàn toàn trên TS: mọi Controller/Service/Entity đều có type. Hiểu TS là hiểu vì sao NestJS viết theo kiểu đó.

2. Type alias — đặt tên cho kiểu

type cho phép đặt tên cho một kiểu, tái sử dụng nhiều nơi. Đặc biệt mạnh với union type (một trong nhiều giá trị):

demo/ts16-verify.ts — type alias + union (đã verify XANH) 
// type alias: đặt tên cho kiểu number
type UserId = number

// union type: role chỉ được là 1 trong 3 giá trị — gán 'superadmin' sẽ lỗi compile
type Role = 'admin' | 'teacher' | 'student'
💡 Vì sao union type hữu ích?

Thay vì role: string (chấp nhận mọi chuỗi, kể cả 'superadmin' sai), union 'admin' | 'teacher' | 'student' giới hạn đúng tập giá trị. TS bắt lỗi ngay lúc gán sai — đây là nền cho enum/role trong NestJS (Module 5 RBAC).

3. Interface — mô tả hình dạng object

interface mô tả "hình dạng" của một object — có những field nào, kiểu gì. Đây là cách chuẩn để định nghĩa entity trong NestJS:

demo/ts16-verify.ts — interface User (đã verify XANH) 
// interface: mô tả object User — mọi field bắt buộc đúng kiểu
interface User {
  id: UserId      // dùng type alias đã định nghĩa
  email: string
  name: string
  role: Role       // dùng union type
}

const users: User[] = [
  { id: 1, email: 'a@ex.com', name: 'An', role: 'student' },
  { id: 2, email: 'b@ex.com', name: 'Binh', role: 'teacher' },
]
💡 Interface vs type — khi nào dùng gì?

Theo TS docs: interface dùng để mô tả object (có thể mở rộng bằng extends), type dùng cho union/alias. Quy ước phổ biến: object/entity dùng interface, union/alias dùng type. NestJS dùng interface cho DTO/Entity.

4. Generics — hàm dùng chung cho nhiều kiểu

Generics () cho phép viết hàm/class dùng chung cho nhiều kiểu mà vẫn giữ type an toàn. Thay vì viết riêng cho từng kiểu, viết một lần với tham số kiểu T:

demo/ts16-verify.ts — generics (đã verify XANH) 
// Generics: T là tham số kiểu — hàm này dùng được cho MỌI mảng
function first(arr: T[]): T | undefined {
  return arr[0]
}

const firstUser = first(users)   // T = User → firstUser: User | undefined
const firstNum = first([10, 20, 30]) // T = number → firstNum: number | undefined

console.log('firstUser:', firstUser?.name) // An
console.log('firstNum:', firstNum) // 10
💡 Vì sao generics quan trọng?

Nếu viết first(arr: any[]), bạn mất type an toàn (firstUser không biết là User). Generics giữ type: first(users) trả User | undefined, first([10,20]) trả number | undefined. NestJS dùng generics khắp nơi (vd Repository, Array).

5. Áp dụng vào dự án e-learning — thay `any` bằng type đúng

Trong src/server.ts (bài 15), bạn dùng req.body ?? {} — TS không biết body có gì. Giờ định nghĩa interface cho body và dùng type an toàn:

src/server.ts — thêm interface cho body (áp dụng bài 16) 
// Interface mô tả body của POST /api/courses — TS bắt lỗi nếu thiếu field
interface CreateCourseBody {
  title: string
  price?: number   // optional — có thể không gửi
  description?: string
}

// Dùng type an toàn thay vì req.body ?? {}
app.post('/api/courses', auth, async (req: Request, res: Response) => {
  const body = req.body as CreateCourseBody // ép kiểu body
  if (!body.title) {
    res.status(400).json({ error: 'title là bắt buộc' })
    return
  }
  // ...
})
💡 `as` — ép kiểu (type assertion)

req.body as CreateCourseBody nói với TS "tôi biết body có hình dạng này". Đây là bước đầu; bài 22 (DTO/ValidationPipe) sẽ làm validation thật sự ở runtime, không chỉ type. Nhưng đã an toàn hơn nhiều so với any.
