Module 4 · Bài 21

Controller · Service · Provider — Container tự resolve dependency thế nào

Bài 20 controller không cần dependency. Giờ thêm CoursesService và quan sát Nest container tự đưa instance đúng vào constructor — không gọi new, không import trực tiếp.

⏱ ~40 phút · 🎯 Mục tiêu: giải thích được "vì sao chỉ viết constructor là đủ" và vì sao project phải bật emitDecoratorMetadata.

🌉 Bắc cầu từ container mini bài 19

Bài 19 bạn gọi container.resolve('courseService') — container tự biết factory nào để tạo. Nest làm điều tương tự nhưng dùng metadata emit từ TypeScript: @Injectable() đánh dấu class là provider, còn design:paramtypes do compiler sinh ra cho Nest biết constructor nhận kiểu gì. Nếu metadata missing, Nest không biết phải inject cái gì.

1. Ba vai trò bạn sẽ thấy

Vai tròVí dụTrách nhiệm
ControllerAppControllerNhận HTTP request, gọi service, trả JSON — KHÔNG chứa logic nghiệp vụ.
Provider (Service)CoursesServiceChứa logic nghiệp vụ, đọc/ghi dữ liệu — được container quản lý vòng đời.
Provider tokenclass CoursesServiceDùng làm injection token — Nest đối chiếu metadata của constructor với provider đã khai.

Theo tài liệu Providers của NestJS, provider là ý tưởng cốt lõi để inject dependency; một class được đánh dấu @Injectable() và đăng ký trong @Module({ providers: [...] }) sẽ nằm trong vòng đời quản lý của container. Controller cũng có thể là provider nếu nó được inject.

2. Hai mảnh ghép để DI hoạt động

src/nest/courses.service.ts — provider mới, @Injectable() 
import { Injectable } from '@nestjs/common'

// Dữ liệu tạm — bài 23 sẽ thay bằng TypeORM + PostgreSQL
export interface Course {
  id: number
  title: string
  price: number
}

const courses: Course[] = [
  { id: 1, title: 'NestJS cơ bản', price: 500000 },
  { id: 2, title: 'Design Pattern cho Backend', price: 800000 },
]

// @Injectable() đánh dấu class là provider mà container có thể quản lý
@Injectable()
export class CoursesService {
  findAll(): Course[] {
    return courses
  }
}
src/nest/app.module.ts — đăng ký provider vào module 
import { Module } from '@nestjs/common'
import { AppController } from './app.controller.js'
import { CoursesService } from './courses.service.js'

@Module({
  controllers: [AppController],
  providers: [CoursesService], // provider token = class CoursesService
})
export class AppModule {}
src/nest/app.controller.ts — controller xin dependency qua constructor 
import { Controller, Get } from '@nestjs/common'
import { CoursesService } from './courses.service.js'

@Controller()
export class AppController {
  // KHÔNG gọi new CoursesService() — Nest tự inject instance đúng
  constructor(private readonly coursesService: CoursesService) {}

  @Get()
  getRoot(): { message: string } {
    return { message: 'E-Learning NestJS đã chạy' }
  }

  @Get('courses')
  getCourses() {
    return this.coursesService.findAll()
  }
}
🎯 VÌ SAO phải bật emitDecoratorMetadata?

TypeScript khi có experimentalDecorators + emitDecoratorMetadata: true sẽ phát ra design:paramtypes — một mảng các class constructor đang nhận. Nest đọc metadata này để biết AppController cần CoursesService và tìm provider có cùng token. Nếu thiếu flag, metadata bị thiếu → this.coursesService là undefined → request 500.

⚠️ tsx (esbuild) KHÔNG emit metadata — mấu chốt

tsx dùng esbuild để transform code nhanh, không ra design:paramtypes. Chạy Nest bằng tsx watch src/nest/main.ts → DI không hoạt động, mọi DI về undefined. Đã verify: build bằng tsc rồi chạy node thì DI XANH. Do đó bài này đổi script dev:nest:

Terminal — đổi script cho đúng cách (tsc build rồi mới node chạy) 
# Khi bạn mở bài này, package.json đã được AI cập nhật script như dưới — kiểm tra lại nhé
npm pkg set scripts.dev:nest="tsc && node --watch dist/nest/main.js"

# Nếu server cũ đang chạy từ bài 20, hãy Ctrl+C dừng rồi chạy lại bằng cách mới
npm run dev:nest
💡 Vì sao container biết gọi provider nào?

Khi bạn viết private readonly coursesService: CoursesService, TypeScript phát metadata chứa kiểu CoursesService. Nest dùng chính kiểu đó làm injection token — giống token 'courseService' ở bài 19 nhưng an toàn hơn (kiểu class, không trả chuỗi gõ tay). Đó là lý do NestJS chọn DI kiểu class token.

3. Thử thách triển khai

Đề bài

Từ code Nest của bài 20, thêm CoursesService và route GET /courses, đồng thời đổi script chạy sang cách tsc+node.

  • TC1: Tạo src/nest/courses.service.ts có @Injectable(), field findAll() trả mảng khóa học.
  • TC2: AppModule đăng ký CoursesService trong providers.
  • TC3: AppController khai constructor nhận CoursesService và thêm route GET /courses gọi findAll().
  • TC4: Script dev:nest chạy bằng tsc && node --watch dist/nest/main.js (không dùng tsx cho Nest).
  • TC5: Nhận được curl http://localhost:3000/courses trả JSON mảng khóa học — không lỗi 500.

Definition of Done: một terminal chạy Nest; terminal khác gọi curl nhận đúng mảng khóa học; bạn tự giải thích vì sao thiếu emitDecoratorMetadata thì kết quả vẫn lỗi.

🎤 Góc phỏng vấn – nếu hỏi “@Injectable() để làm gì?”

Trả lời gọn: @Injectable() đánh dấu class là provider; đăng ký trong @Module().providers thì class thuộc vòng đời container; Nest tự nối constructor của controller bằng metadata design:paramtypes. Nhờ container quản lý, ta không tự tay gọi new nhiều chỗ — dễ test và dễ thay thế provider.
